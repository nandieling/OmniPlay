# OmniPlay 安卓 TV 版

安卓 TV / 手机客户端，技术栈为 Java + libmpv（NDK 编译 JNI 桥接层）。
当前版本为独立版（versionName 1.43）：媒体库完全在本机工作，不依赖 OmniPlay Docker 服务端。
功能对齐 ARM mac 版（`OmniPlay开源-mac-ARM`），交互按遥控器 D-pad 逻辑重做，不照搬 macOS 布局。

## 功能范围

- 启动器双入口：TV 界面（LEANBACK_LAUNCHER，遥控器 D-pad 焦点导航）与手机界面（触摸海报网格、横屏播放器），由 `LauncherActivity` 自动分发。
- 独立媒体引擎 `LocalEngine`：本地文件夹、WebDAV、SMB 媒体源，本机 SQLite 库扫描，支持按季/集解析（中英文件名、SxxExx、第 N 集等）。
- 首屏永远是海报墙（1.21）：`onCreate` 只 `showHome()`，一个媒体源都没有时墙上自带「添加媒体源」入口，不再先甩一整屏设置页（`showSetup` 退化为服务端模式与异常兜底用的错误页）。媒体源的添加、登录、挑目录全在首页「媒体源」抽屉里做：类型按 WebDAV、SMB、本地目录排列，进入 App 后自动扫描局域网 `LanDiscovery`（子网枚举 + 每个「主机 × 端口」一条探测任务的 TCP 探测 + OPTIONS `DAV` 头 / PROPFIND 验证 + NetBIOS 主机名查询），边扫边列出 WebDAV / SMB 设备，行高足够显示第二行的地址或已挂载目录；点选设备或手动填写地址后弹出登录框（地址 / 用户名 / 密码），登录成功再弹出“选择媒体目录”浏览器（WebDAV 目录树 / SMB 共享与子目录 / 本地文件夹管理器），选定目录后保存媒体源、抽屉不关、扫描刮削转后台，海报一张张上墙。TMDB API Key 与代理网关在首页设置中配置。
- 内封字幕后台转档（1.34）：抽取器在扫描收尾会自己排一小批（这个开关 1.37 起从设置里去掉，批量交给媒体源那台转档服务，电视端保留播放页的手动入口）。抽取器是现写的 Java Matroska 读取器（不碰 JNI 与 libavformat），产物 `片名.zh.srt` / `.ass` / `.sup` 写回视频旁边，播放时读这个小文件走 Android 字幕覆盖层，于是高性能直出模式下也看得见字幕。数据库升到 6（`subtitleSidecar` 表记状态与续跑偏移，中断接着跑）。
- 认媒体源里现成的外挂字幕（1.35，1.37 起自动）：NAS 上那台「字幕转档瘦身版」（`../OmniPlay-字幕转档`）写回的 `片名.zh.srt` / `.ass` / `.sup`，现在片子一播起来就自动登记进字幕菜单，菜单里那条改成「再找一遍媒体源里的外挂字幕」当手动刷新。登记的记录占 900 号以后的轨位，菜单里显示成「媒体源外挂字幕 · 中文（SRT）」，点开直接走同一套覆盖层。这样电视和 NAS 两边不会把同一个文件各抽一遍。
- 播放页换模式不叠画面、不留声（1.36）：兼容字幕播放 ↔ 高性能直出要整条换解码链路，以前只把旧的播放视图从界面上摘掉、没停它，旧 libmpv 就在后台继续解码出声——两层画面叠着、新片抢不到硬解卡住、退出软件声音还在循环。现在换片与换模式都先走 `releasePlaybackState()`（记位置、停轮询、停本地代理、停 HLS、毁实例）再建新视图，`onPause()` 一离开播放页就收，`onDestroy()` 再用实例名册兜一遍底。原生侧拆实例时先 `pause` 再 `terminate_destroy`，并且不再 `dlclose` libmpv。
- 播放菜单看得清选中、轨道再多也翻得到（1.37）：字幕 / 音轨菜单的标题会直接写「已选 ××」，选中那行左边多一个勾（强调色），行容器套了限高滚动区（最多屏高六成），方向键焦点走到哪行就自动滚到哪行——蓝光十几条字幕轨不用再靠运气够。
- ASS 侧车字幕能显示了（1.37）：覆盖层以前只认 SRT / WebVTT，转档出来的 `片名.zh.ass` 一行都读不出来，于是兼容模式下 PGS 有字、ASS 没字。新增 `subtitle/AssSubtitle`（读 `Format:` 字段顺序、`h:mm:ss.cs` 时间戳，抹掉 `{\\pos}` 之类控制序列、`\N` 转换行，零时长与 `Comment:` 丢掉），SRT / VTT 路径不变。
- 现成外挂字幕自动上菜单（1.37）：以前得在字幕菜单点一次「找媒体源里现成的外挂字幕」才登记，而且只按文件里字幕轨标的语言去探——蓝光轨常标 `und`，NAS 写的却是 `片名.zh.sup`，于是明明有却报「没有」。现在片子一播起来就在后台认一遍（文件里推出来的语言最多取三个 + 偏好语言那几个码总探），扫库收尾也顺手认一小把（12 个文件），直出模式下找到就顺手挂上，不用再点。设置里那条「内封字幕转档」三选一去掉了：它只决定扫描收尾要不要自己抽一小批，而批量这件事是 NAS 那台转档服务的活；要单独抽某一条，字幕菜单里点「后台转档这条的内封字幕」。
- 没填 TMDB Key 也开得开「手动匹配」（1.38）：弹层一进来先 `if (!tmdbConfigured()) return`，等于把豆瓣这条路一起锁死了——没填 Key 时点详情页那颗按钮只弹一条 toast，弹窗根本不出现。现在弹层无条件打开，候选清单拆成「TMDB 候选」与「豆瓣候选」两栏：TMDB 没配置时那一栏只剩一句「没填 API Key，跳过」，豆瓣照搜照选。
- 豆瓣海报取不到了（1.39）：绑定成功、评分简介都在，就是没图。解析其实没坏——页面里 `sub-cover` 那行照常给出 `imgN.doubanio.com/view/photo/s_ratio_poster/public/pNNN.jpg` 正规地址，也照常写进了库；坏在取图那一步：豆瓣图床查 Referer，不带它直接回 **418**（不是 403，日志里看着就像「这张图没了」）。`ImageLoader.fetch` 现在对 `doubanio.com` / `douban.com` 主机补一条 `Referer: https://movie.douban.com/`，TMDB 与本机 / 服务端地址照旧不发。之前绑过的条目不用重绑：库里存的就是那个正规地址，装上这版直接出图。
- 豆瓣片名清洗（1.39）：现版移动版页面没有 JSON-LD，也没有 `v:itemreviewed` / `v:image`，片名只能退到 `<title>`，于是绑回来的叫「未麻的部屋 - 电影」。新增 `sub-title` 那条正则（豆瓣自己标的片名，不带栏目名），并把「- 电影 / - 电视剧」这类尾巴与全角括号里的年份（原名「Perfect Blue（1997）」）一并剥掉。自检夹具换成真实抓下来的 `m.douban.com` 页面，豆瓣再改结构会当场叫出来。
- 豆瓣关键词搜索（1.38，`DoubanClient.search`）：手动匹配不再要求你先知道条目号。抓 `search.douban.com/movie/subject_search` 那段 `window.__DATA__`，页面要先有一副匿名 cookie 才吐数据，所以先去 `www.douban.com` 首页领一副存着复用；桌面 UA（移动版 UA 会拿到空列表）。候选行带海报、年份、「剧集 / 电影」标签、豆瓣评分与一行国家-类型摘要，点中就是绑这条豆瓣条目，与手贴链接走同一条路。解析用的是自己那一小段 JSON 读取器（`MiniJson`）：条目页那一路照旧用系统 `org.json`，但搜索页的解析得能在离线自检里跑，而 `android.jar` 里那份 `JSONObject` 是 `throw new RuntimeException("Stub!")` 的空壳，页面结构一漂移脚本根本发现不了。
- 已保存的连接（`SavedConnections`）：WebDAV / SMB 只要登录成功一次，账号密码与该次挂载的目录就按「协议 + 主机 + 端口」记进本机偏好（最多 12 台服务器、每台 4 个目录，最新在前）。登录框会回填保存过的账号密码，扫描到的设备行第二行显示上次挂载的目录，点进去登录框就是填好的状态。只有换服务器或换目录时才需要重新输入；升级前已有的媒体源在首次进入媒体源抽屉时自动补录。
- 目录浏览器（WebDAV / SMB / 本地）以 `BrowseEntry`（名称 + 完整 URL + 是否目录）承载每一行，直接进入服务器返回的 URL，不再靠拼接目录名；WebDAV 自身条目按 URL（忽略结尾斜杠与百分号编码）过滤，SMB 走 jcifs 的容器 URL 并隐藏 `.` 开头与 `IPC$` / `ADMIN$` / `PRINT$` 等管理共享，路径行按编码还原显示中文目录名。
- WebDAV / 局域网探测的传输层是自己写的 `Http`（裸 Socket 的 HTTP/1.1，见 `local/Http.java`）：Android 的 `HttpURLConnection` 只允许 OPTIONS/GET/HEAD/POST/PUT/DELETE/TRACE/PATCH，`setRequestMethod("PROPFIND")` 会直接抛 `ProtocolException: Expected one of [...]`，所以 WebDAV 不能走它；同时 NAS 的自签证书也一并绕过（信任所有证书 + SNI），支持 Content-Length / 分块响应与 1xx 跳过，请求行按百分号编码所以中文目录名可用。播放地址仍交给 mpv 自己抓取，`OfflineCacheManager` 的下载只用到 GET/HEAD，继续走系统实现。
- 异常可见（`CrashLog`）：`runAsync` 与局域网扫描线程捕获 `Throwable`（不只是 `Exception`），未捕获异常由全局 `UncaughtExceptionHandler` 记进本机偏好，下次进入登录页会在顶部显示「上次异常退出：…」一行后清除；`SmbClient` 把 jcifs 抛出的任何错误（含 linkage error）翻译成带原因的 `IOException`，登录框直接显示原因而不是整个 App 静默退出；登录页还会用 `SmbClient.warmUp()` 预热一次 SMB 库，起不来就在状态行写「SMB 组件不可用：…」。
- SMB 媒体源（jcifs-ng 纯 Java 实现）：扫描共享目录并用 libmpv 直接播放原片；播放通过设备本地起的 HTTP Range 代理（`SmbStreamServer`，模式与 `RemoteIsoStreamServer` 一致）向 mpv 提供字节流，支持断点续播。SMB 播放依赖局域网连通性与 NTLM 认证（Synology/Samba 可用，host 作为 workgroup）。
- TV 遥控器焦点导航（`ui/FocusGrid`）：每个界面把自己控件声明成「行」，FocusGrid 负责写 nextFocus 链接、按网格移动焦点、把焦点滚进可视区；覆盖层用 `push`/`pop` 把网格压栈，关闭后必定回到打开它的那个控件，覆盖层套覆盖层也不会互相踩。首页用框架的 focusSearch，避免整面海报墙被网格化。
- 返回键只有一个入口（`closeTopmostLayer`）：播放器菜单 → 最上层覆盖层 → 播放器 → 首页搜索 / 排序展开行 → 详情页 → 登录页，`onKeyDown` 与 `onBackPressed` 共用它，不会出现两条链走歪或同一个弹层被关两次。
- 覆盖层只有一份实现（`ui/Overlays`）：遮罩、面板、标题、副标题、状态行、底部按钮行、焦点栈、关闭还原都由它负责；设置、媒体源、登录、目录浏览器、手机输入、文本输入六个弹层都走 `overlays.open(...)`，所以它们的外观、层级、返回行为必然一致。
- TMDB 自动刮削（`TmdbClient`，移植自 mac 版）：多关键词搜索评分、zh-CN 语言合并、限速；设置中填写自己的 API Key / v4 Read Access Token，无法直连 TMDB 时支持代理网关（带路径前缀的 Worker 反代地址，见根 README）。
- 刮削语言可在设置中切换（简体中文 zh-CN / English en-US），TMDB 接口与图片语言一并跟随。
- 豆瓣只做手动绑定（1.31，`DoubanClient`，对齐 mac 版 `DoubanService`）：详情页手动匹配弹层里贴一条条目链接或编号就能绑上豆瓣评分与资料（长链接走「手机输入」推过来），抓取之间至少隔 12 秒，被挡（403 / 验证页）就自动歇 12 小时；海报只认 `doubanio.com/view/photo/...public/` 的原图地址。绑定后详情页元信息行与首页卡片都是 `TMDB ★` 与 `豆瓣 ★` 两颗并排，豆瓣还能补类型 / 地区 / 导演 / 主演 / 简介的空缺；TMDB 本来就没搜到的条目，豆瓣资料直接落库并锁定这条记录，之后的自动刮削不再覆盖它。1.38 起这一路不再依赖 TMDB：弹层里可以直接按关键词搜豆瓣条目并点选绑定，一行候选都不用先知道条目号。
- 首页顶部工具栏（D-pad 版）：搜索、排序（标题/添加时间/年份/评分）、升降序、扫描刮削、媒体源、设置，一行六颗按钮（1.17 起去掉了「筛选」，类型与观看状态不再参与过滤；1.18 起「扫描刮削」从媒体源面板挪到这里，放在「媒体源」左边）。1.23 起这六颗是纯符号按钮，1.24 起形状与配色逐一对齐 mac 版 `PosterWallView` 里的 `systemName`：`magnifyingglass`、`line.3.horizontal.decrease.circle`（排序）、`arrow.up` / `arrow.down`（升降序）、`arrow.triangle.2.circlepath`（扫描刮削）、`folder.badge.plus`（媒体源）、`gearshape`（设置），全部由 `ui/Icons.java` 在 24 单位网格上用 Canvas 矢量画；平时没有底板（mac 是 `.buttonStyle(.plain)`），图标颜色取 mac 的「主文字色 78%」，只有拿到焦点才给出圆角底与强调色描边。名字与说明留在 `contentDescription` / 长按提示里；工具栏左上角是 mac 版那个位置的扫描刮削进度（小转圈 + 一行状态，措辞与 mac 一致：扫描、刮削、或队列里还有条目时一直显示，1.24；全部刮完才在收尾停 8 秒后收起，位置固定不随横幅出现消失而挪按钮）；「继续播放」是横向卡片行，与海报网格共用同一套焦点链。
- 媒体源管理覆盖层（`openSourcesOverlay`）：逐个媒体源启用/停用、重命名、移除；面板内自带「局域网设备（自动扫描）」与 添加 WebDAV / 添加 SMB / 添加本地目录 三颗按钮，扫到的设备点进去是登录、登录后挑目录、挑完才挂载（照 mac 版的添加抽屉）；新挂载的源直接出现在面板里，抽屉不关、不切全屏，扫描刮削在后台跑，海报一张张出现在背后的墙上，工具条那颗按钮同步变成「扫描中」。
- 类型 / 导演 / 主演：随刮削结果一次请求取回（`append_to_response=credits`），存进 `movie`/`tvShow` 的 `genres`/`directors`/`casts` 列，详情页展示。
- 分集信息与分集剧照：详情页按季拉取 TMDB 分集详情（标题 / 简介 / 首播日期 / 剧照），剧照季映射沿用 mac 版回退规则（本季节 → 第 1 季 → 集数最多的季），仍无剧照时改查 `/images` 按投票加权择优；单集副标题支持手动覆盖，覆盖值优先于刮削结果。
- 详情页两颗资料按钮：「手动匹配」打开搜索弹层（关键词 / 年份 / 候选清单，点一行关联，1.22 起）、「自定义编辑」手填片名 / 上映日期 / 评分 / 类型 / 导演 / 主演并锁定（对应 mac 版的手动编辑资料）；两者都会锁定这条记录，之后的自动刮削不再覆盖它，与 mac 版 `isLocked` 同一条规则。单集仍可写自定义分集副标题。
- 启动自动扫描 + 扫描后自动刮削（均可在设置中关闭），行为与 mac 版一致；刮削在后台推进，首页每两秒补一轮海报，回到首页时也会重读一次媒体库，卡片不会停在刮削前那版。1.28 起扫描与刮削是重叠推进的：每登记 20 条新文件就从扫描线程借 4 秒刮一批，每个源扫完再刮一轮，收尾照旧是一次不限时的整轮刮削，所以大目录第一次扫描时海报就是一点点长出来的，而不是「扫完才动」。
- 服务端接入模式（`OmniPlayApi`）：输入 OmniPlay Docker 地址 + 账号密码登录，海报墙走 `/api/library/items`，播放直连 `/api/playback/files/{id}/stream`（HTTP Range + 会话 Cookie），与 ARM mac / TV 端播放进度同步。
- libmpv 直接播放原片文件，带续播；外挂字幕通过 OmniPlay 服务端发现（sidecar），内嵌字幕由 mpv 自动选择。
- 播放按键：中键/回车切换暂停，左右快退/快进 10 秒，返回键退出播放；手机播放器提供触摸暂停与 ±10 秒按钮。
- 播放偏好（`TvSettings`）：默认音轨语言、默认字幕语言（自动 / 中文 / 英文 / 日文 / 关闭）、画质模式（流畅 / 均衡 / 画质优先，映射为 mpv 的 `demuxer-max-bytes`、`demuxer-max-back-bytes`、`demuxer-readahead-secs`）、详情页显示分集简介与进度、显示真实源文件路径。
- 手机辅助输入（`PhoneInputServer`）：遥控器打长串文本太慢时，TV 显示二维码与 `http://<TV-IP>:<随机端口>/p/<token>`，手机浏览器打开表单填写后 POST 回电视，直接写进对应输入框。详见下方“手机辅助输入”。
- 离线缓存（`OfflineCacheManager`）：1.15 起 TV 界面不再提供这个功能（电视本来就接在 NAS 上，盒子内没有可看的大容量空间），详情页与设置里的缓存入口、状态条里的缓存进度一并撤下。下载与容量预检的实现仍留在 `local/` 里，播放时也会继续优先用已缓存的副本，历史数据不会突然换成网络流。
- 4K DV/HDR 双播放模式（1.32 起开关从设置搬进播放页）：播放页工具条上一个按钮写着当前模式，点开在“字幕兼容播放模式”（色彩管理与字幕兼容性更好、负载更高）与“高性能直出播放模式”（仅针对 4K 或 DV/HDR 生效，其它格式仍走兼容模式）之间切换，切换时先记下进度再原地重开。直出走 `vo=mediacodec_embed`，视频直接进解码器，mpv 不再渲染内封字幕与 OSD，要看字幕就用兼容模式；蓝光 ISO 一律走兼容模式。兼容模式在 1.33 降过一轮负载（峰值探测改用文件元数据、FBO 退到 `rgb10_a2`、4K / HDR 改画 SurfaceView 少一层合成），但 4K HDR 的色调映射仍在电视 GPU 上跑，卡顿就切直出；1.34 起直出也能看字幕，把内封字幕后台转成贴着视频的 sidecar（见下）。
- 手机端首屏也是海报墙（1.43）：`PhoneMainActivity.onCreate` 原来是「先问一句再进墙」——`LocalPlayApi.hasServerUrl()` 其实就是「有没有媒体源」，于是全新安装一进来先撞上整屏「添加媒体源」表单，库里已经有片子的也要先跑一次 `authStatus` 才轮到墙。现在启动直接 `showHome()`：墙空的时候入口长在墙上，一个媒体源都没有写「还没有媒体源。添加本地目录、WebDAV 或 SMB 后会自动扫描刮削。」配「添加媒体源」按钮，有源但还没刮出条目写「媒体库还是空的，可能正在扫描刮削。」配「刷新」。设置页退成二级页，页头右侧加了「返回」（表单很长，不该逼用户滚到底才能回墙），底部那颗「进入」改成「进入媒体库」，返回键从设置页也回墙而不是退出应用。做法与 1.21 起的电视端一致。
- 撤下快进倍速（1.42）：1.41 加的「长按松手后连点右键 = 2 / 3 / 4 倍速」去掉——同一次右键按压既要当快进又要当倍速入口，遥控器上手感含混，`mpv speed` 与倍速角标那套代码一并撤走。快进的步长爬升（10× → 30× → 100× → 250×）保留。
- 绑定豆瓣不再整屏抖一下（1.41）：绑定成功的回调里原先是「删缓存 + `showDetail`」，条目 id 又没变，于是每次绑完都先整屏盖一次「正在进入详情」再掀开——有人看见的是「卡一下」，有人因为详情查询快得几乎看不见就说没问题。现在改成原地 `refreshDetail`（删缓存、不盖整屏），解绑与同类型的 TMDB 关联一并改掉；只有跨类型改绑（条目 id 真变了）才走整页重开。
- 豆瓣海报多一条兜底（1.41）：页面 meta 里那张 `og:image` 现在是 `qnmob3-sign.doubanio.com` 的签名地址（带 `sa_cv` / `sa_ct`，会过期），以前直接判成不可用。`normalizePoster` 把 `qnmob*` 主机换成 `img3.doubanio.com`——同一张图片在正规 CDN 上就有，签名只是临时门票。于是 `sub-cover` 那行万一哪天没了，海报还能从 meta 里拿到。（1.39 那个 `Referer` 才是「绑了豆瓣没海报」的主因，签名地址这条是补的第二个洞。）
- 快进加速（1.41）：长按左右方向键那套平滑快进原先一路 10× 实时速度，跳个片头得按住小半分钟。现在步长随按住时间爬升——10× → 30× → 100× → 250×（0.7 秒 / 1.8 秒 / 3.5 秒换档），按住越久跳得越猛，进度预览照旧每步刷新。（1.41 同版还加过一套「长按松手后连点右键上 2 / 3 / 4 倍速」，1.42 按反馈撤下：倍速与遥控器上原有的导航手感打架，见下条。）
- 播放页右下角的「画面比例」开关（1.40）：两档——保持比例（按影片自己的宽高摆，多出来留黑边）与拉伸填满（铺满全屏、画面变形），点中即生效、不重开播放器，偏好记下来给下一条用。以前直出模式（`vo=mediacodec_embed`）是解码器把帧直接写进 SurfaceView，而 SurfaceView 默认把帧铺满视图，2.35:1 的片在 16:9 电视上就被上下拉开——全屏看着就是「画面被拉伸」。治法是量视频视图自己：`MpvVideoView` 按 mpv 报的显示宽高比（`dwidth` / `dheight`，读不到退回 `video-size`）把那张 Surface / Texture 视图在容器里居中摆一块，黑边由容器的黑底出（`SurfaceView.setAspectRatio` 在 SDK 里是隐藏的，应用侧调不到，这招与 ExoPlayer 的 `AspectRatioFrameLayout` 同一路子）；兼容模式那一路由 mpv 留黑边，拉伸就改它的 `aspect`。两层字幕跟着画面走：文字层抬高一个黑边高度，PGS 层直接缩到画面那块，否则字会掉进黑边里。
- 蓝光 ISO/BDMV：`RemoteIsoStreamServer` 在设备本地起 HTTP 分块流服务，配合 mpv 直接播放 ISO。
- 蓝光主片挑选（`BluRayStreams`，移植自 mac 版 `MediaNameParser.selectedBluRayStreamIndices`）：三种媒体源的 walker 都会走进 `BDMV/STREAM`，但一盘里的分卷不会整盘入库——每个「BDMV 上一级目录」为一组，按体积挑主片：最大的一条不小于第二名的 1.55 倍就只留它，否则按 0.72 的门槛把分卷合辑整组留下；体积未知时退回分卷号最小的那条。`BDMV` 下不在 `STREAM` 的文件（PLAYLIST / CLIPINF）直接丢弃，扫描报告用「蓝光非正片分卷跳过 N」说明少掉了多少条。
- PGS 图形字幕解析（`PgsSubtitleParser` / `PgsSubtitleView`）：解析 PGS segment 流并在播放器上叠加渲染。
- 服务端 HLS 兼容播放：Docker 模式下 MKV/蓝光等浏览器不支持的格式经服务端转 HLS 播放（TV 端解码与 HLS 兼容模式自动选择）。
- Lucky STUN 穿透客户端（`LuckyStunClient`）：登录 Lucky 管理端、拉取穿透规则、更新外网地址，用于通过 Lucky 穿透访问 OmniPlay 服务端。
- APK 自更新：`ApkUpdateProvider` 暴露本地 content:// APK 供“软件更新”入口安装。
- 播放进度规则：0.95 视为已播完，其余精确续播。

## libmpv 依赖

默认从 Gradle 依赖 `dev.jdtech.mpv:libmpv:0.5.1` 拉取 Android `libmpv.so` 及其 FFmpeg 运行时，覆盖 `arm64-v8a`、`armeabi-v7a`、`x86_64`（`arm64-v8a` 是绝大多数安卓 TV 盒子目标）。
JNI 桥接层 `libmpvbridge.so`（`app/src/main/cpp/mpv_bridge.cpp` + CMake）在构建时由 NDK 编译，动态加载 `libmpv.so`，向 mpv 传入 Surface、Cookie 头、字幕 URL、续播位置与直连流地址。
如需手动替换 libmpv 构建，按 `app/src/main/jniLibs/README.md` 的布局放入各 ABI 目录即可覆盖 AAR 中的版本。

## SMB 依赖

SMB 媒体源使用 `eu.agno3.jcifs:jcifs-ng:2.1.10`（纯 Java CIFS/SMB 客户端，LGPL），首次构建会从 Maven Central 拉取，并一并引入其传递依赖 `org.bouncycastle:bcprov-jdk18on`（NTLM 认证所需，Apache 2.0）。两者都打进 `classes.dex`，无需 NDK。若目标设备 SMB 服务器仅支持 Kerberos 或较新的 AES-128-CT 加密且需要额外 BC 算法，可在 `app/build.gradle` 中按需提供对应 BC 模块。

## 手机辅助输入

遥控器上的系统输入法打 NAS 密码、TMDB v4 Token 这类长串文本很不现实，App 内置一个只监听局域网的迷你 HTTP 服务（`local/PhoneInputServer.java`，与 `SmbStreamServer` 同一套进程内 ServerSocket 写法）代填文本：

- 入口：登录弹窗的“手机输入”、添加媒体源页的“手机输入”、设置页的“用手机输入 TMDB 配置”与“用手机输入缓存目录”、通用文本弹窗（重命名媒体源、改片名、分集副标题）里的“手机输入”。
- 交互：覆盖层显示二维码（`local/QrCode.java`，zxing 编码）与可手输的纯文本地址，底部只有“关闭”一个焦点项；手机提交后电视状态行显示“已填入 N 项（来自 <手机 IP>）”，覆盖层不关闭，可连续提交。
- 页面字段由覆盖层注册，只列出当前场景需要的输入；留空的字段不会被改写，避免误清空已填内容。单字段场景额外提供“补充内容”文本域，长串密钥可直接整段粘贴。
- 访问控制：路径带装机时生成、之后保持不变的 token；服务只接受 site-local（10/8、172.16/12、192.168/16）与回环地址来的请求；端口每次启动随机分配（`ServerSocket(0)`）；覆盖层关闭即清空会话，旧页面再提交只会得到“电视端已经离开这个输入页”。
- 手机与电视必须在同一局域网，且路由器不能开 AP 隔离；页面为明文 HTTP，密码在内网明文传输，与 WebDAV/SMB 本机直连的既有假设一致。

## 界面层（1.11 重构）

TV 界面以前是一个 8000 多行的 Activity 里手搓六套弹层、三套 D-pad 逻辑，弹层套弹层时焦点会丢、返回键会跳级、改个排序就整页重建（海报重新加载、滚动位置和焦点都要手工还原）。1.11 把这些收进 `ui/`：

- `ui/Theme.java`：唯一的配色、字号缩放、面板形状与焦点样式来源（对应 mac 版的 `ThemeManager`）。按钮 / 行 / 输入框 / 海报卡 / 播放器玻璃控件各有一种焦点样式，界面代码不再自己 `new GradientDrawable()`。
- `ui/Widgets.java`：唯一的控件工厂（对应 mac 版的 `MovieCardView`、按钮、分区标题等 SwiftUI 视图）：`button` / `toolbarButton` / `listRow` / `input` / `metaPill` / `badge` / `progressBar`，加上设置表单用的 `settingsCard` / `sectionCaption` / `addCardRow` / `cardButtonRow` / `switchRow` / `segment`，以及一套固定字号梯度（`TEXT_DISPLAY`…`TEXT_MICRO`）与控件高度（`HEIGHT_BUTTON` 等）。
- `ui/FocusGrid.java`：D-pad 导航的唯一所有者。网格按栈管理：底层界面的网格永远在栈底（界面在弹层打开期间重建网格也不会丢），弹层 `push`/`pop`，空行、重建后的控件、跑到网格外的焦点都有兜底。
- `ui/Overlays.java`：覆盖层的唯一实现，`open(Options)` 返回一个可以直接 `addView` 的面板，`closeTop()` 供返回键调用；面板自带状态行（写入才显示、清空就隐藏），底部按钮行用 `footer()`。`Options.scrollable=false` 用于自带滚动列表的固定高度面板（目录浏览器），避免两层 ScrollView 抢焦点。
- 设置面板改开关是就地改样式（`SwitchRow.setOn` / `Segment.setSelectedIndex`），面板不重建，滚动位置与焦点原地不动。
- 首页改为增量渲染：`buildHomeShell()` 只建一次工具栏 / 状态行 / 滚动容器，排序、筛选、升降序只重建 `homeControls`（选项行）或 `homeBody`（继续播放 + 海报墙），输入搜索词只重跑查询。滚动位置、焦点、已加载的海报都不会因为一次切换而丢掉。

## 遥控器滚动、设置表单与刮削可见性（1.14）

三件「用起来不对劲」的事追到底是同一类问题：滚动位置的坐标算错、以及面板的行序与视觉顺序不一致。

- `FocusGrid.scrollToVisible()` 之前按 `view.getTop()` 判断焦点在不在可视区，而 `getTop()` 是相对**直接父容器**的：面板里凡是埋在行容器里的按钮（主题胶囊、分段控件、卡片里的动作行），坐标都是几十而不是几百，于是被判定成「已经在视口上方」并往回滚——这就是按方向键「有概率回弹、滑不下去」的直接原因。现在改成逐层累加 `getTop()` 得到相对滚动容器的位置。
- ScrollView 的子 View 只在**下一次布局**之后才把自己的 `getTop()` 改成含滚动量的值，所以单纯累加在「滚动后未重新布局」和「滚动后重新布局」两种时刻会差一个滚动量，表现为第二次按键滚了两倍距离。`viewportTop()` 用内容视图的布局位移加当前 `scrollY` 做归一化，两种时刻都正确。
- 连续按键时不再用 `smoothScrollTo`：动画会被下一次按键打断，观感就是页面在来回弹。遥控器场景要的是即时定位。
- 面板的 D-pad 行序不再手写。`FocusGrid.rowsFrom(panel)` 从面板自己的视图树按真实几何分组（同行 = 垂直区间以行首中线为锚重叠，锚点不随合并长大），布局完成后再声明一次；之前 `renderSettingsOverlay()` 末尾那份手工 `rows` 列表与视觉顺序差了好几行，按 DOWN 会在面板里上跳下跳。设置、媒体源两个面板都改用它。
- 弹层被返回键关闭时不会再留下失效字段：`Overlay.onClose` 回调让 `settingsOverlay` / `sourcesOverlay` / `loginOverlay` / `browserOverlay` / `phoneInputOverlay` / `textInputOverlay` 一起清空。之前用 BACK 关掉设置后，`openSettingsOverlay()` 因为字段非空直接返回，「设置」按钮看起来就点不动了。
- 焦点丢失时不再一律跳回第一行：`FocusGrid` 记住上次所在的行列，控件重建后从原位置继续。海报墙重建时用卡片上记的条目 id 找回焦点（`restorePosterFocus`），刷新页面不会把用户甩回顶部。

设置面板重排成 mac 那种分组表单：`媒体源` / `TMDB 刮削` / `外观主题` / `刮削与播放偏好` / `基础设置` / `离线缓存` / `4K DV/HDR 播放模式` / `关于与更新` 八个卡片，卡片上方是小标题，说明文字在卡片下方。布尔项换成真开关（`Widgets.SwitchRow`，右侧画一个可切换的滑钮），互斥项换成分段控件（`Widgets.Segment`：刮削语言、音频轨道、字幕轨道、网络缓冲、4K 播放模式），点一下只改样式和偏好，不重建设置面板。卡片里独立成行的按钮固定 48dp 高（之前用 `wrap_content`，被压成 27px，遥控器上几乎按不中）；版本号与开源许可证从面板顶部挪到最后的「关于与更新」里。

刮削过程中海报边刮边出：`startStartupSync()` 与设置里的「刮削海报」进度回调都会调 `scheduleScrapePosterRefresh()`（1.2 秒限流），条目集合没变就只把新数据写回已有卡片（`bindPosterCard`：海报、片名、年份、评分角标、观看状态、进度条），条目增减了才整面重建并补回滚动位置与焦点。之前只在刮削全部结束后刷一次，所以状态条写着「正在刮削 3/12」而海报要等最后才一起出现。

## 设置精简与蓝光主片扫描（1.15）

- 设置里的「媒体源」卡片删掉了。工具条上本来就有「媒体源」按钮，那个弹层里有启用 / 重命名 / 移除 / 添加 / 重新扫描并刮削 / 清空索引，设置里再放一份「添加媒体源」「重新扫描」「刮削海报」「管理媒体源」只是多一层入口，还让人怀疑两个「媒体源」是不是两回事。扫描入口现在只在媒体源管理里，「重新扫描并刮削」的进度回调也接上了 `scheduleScrapePosterRefresh()`，海报仍然是边刮边上墙。
- TMDB 两块输入改成标题在上、输入框在下（`labelledRow()`），输入框文字左对齐。遥控器调出来的软键盘里，居中的长 URL 首尾都会被吃掉一截，看不出打成什么样了。
- 开关现在把状态写在滑块里：关是凹下去的灰底 + 滑块靠左 + 「关」，开是主色底 + 滑块靠右 + 「开」。之前只靠一个浅色轨道的深浅区分，用户在电视前根本看不出这一项到底勾没勾。
- 离线缓存整块从 TV 界面撤下（设置卡片、详情页的缓存本片 / 本季 / 本集、状态条的缓存进度），原因见「功能范围」。

蓝光盘被刮出一堆条目，根因不在解析器，在扫描阶段：

- mac 版走完整棵树，把 `…/BDMV/STREAM/…` 按盘分组，只在组内挑主片；BDMV 里不在 STREAM 的文件丢弃，非 BDMV 文件照常收录。
- TV 版此前三种媒体源的 walker 各自把 `BDMV` / `STREAM` / `disc N` 目录剪掉了。本地和 WebDAV 是「一盘都不收」，SMB 是「全盘收」：jcifs 返回的目录名自带结尾 `/`，`lower.equals("bdmv")` 匹配不上 `BDMV/`，于是直接走进 STREAM，把每条 m2ts 都登记成文件；花絮、宣传片、分卷全都进库，首页就爆了。
- 现在剪目录的规则收到只剩系统垃圾（`lost+found`、`@eadir`、`.nomedia`、`.` / `_` 开头），SMB 的条目名统一去掉结尾 `/`，三个 sink 都带上文件体积（本地 `file.length()`、SMB `entry.length()`、WebDAV 解析 `getcontentlength`），入库前由 `ScanCollector` 分流：普通文件直接登记，光盘分卷先按盘攒着，走完这个源再挑主片。被跳过的分卷不进 `currentFileIds`，所以上一版留下的「每条 m2ts 一个条目」会在同一次扫描的失效清理里自动消失。

规则本身放在 `local/BluRayStreams.java`（不依赖任何 Android 类），配套加了 `/tmp/pitest/run-bluray.sh`（`BLURAY_OK`）：分组键、BDMV 与 STREAM 判定、1.55 独苗、0.72 分卷合辑、体积未知退回分卷号，都在桌面上跑。真机侧在模拟器里造了两张盘（一张 4G 正片 + 400M + 200M 花絮，一张 20G + 19G 分卷），扫完报告是 `文件 8，蓝光非正片分卷跳过 2`：五条 m2ts 只生成两个条目，两张盘各自一条 / 一组。

## TMDB 反代路径、凭证与 WebDAV 目录名（1.16）

反代网关和 API Key 都填对了却报「TMDB 无法访问」，是三个问题叠在一起：

- 连接检测发的是相对地址。`get("/configuration")` 在直连模式下会拼上默认域名，走反代时 `apiBase()` 返回的是空串，`new URL("/configuration")` 直接抛 MalformedURLException，异常被吞掉后统一显示成「无法访问」，跟钥匙对不对其实没关系。
- 反代地址没补 TMDB 的版本段。`https://…/tmdb0512` 只是网关根，TMDB 的接口在 `/3/…` 底下，中间少一段。用 curl 各打一次就能分开：`…/tmdb0512/configuration` 返回 nginx 的 404（网关压根没匹配上路由），`…/tmdb0512/3/configuration` 才是 TMDB 自己回的 `401 status_code:7`。现在 `TmdbClient.normalizeProxyBase()` 会把地址补到 `/3`，路径里已经带 `/3` 就不重复补，六处拼 URL 的地方统一走它。
- 走反代时凭证整个不发。原先六处都是 `isProxy() ? "" : "&api_key=…"`，等于假定「网关会替你加钥匙」。这台网关只做转发，请求到 TMDB 时是裸的；v4 Read Access Token 要的 `Authorization: Bearer …` 也从没发出去过。现在密钥一律跟着走：长度超过 50 位判定为 v4 Token，改用 Bearer 头；其余当 v3 Key 拼 `api_key=`，两种 TMDB API 都能直接粘贴使用。

连接检测也不再是一句话兜底：`checkConnectionDetailed()` 按 空 Key / 2xx / 401、403 / 404 / 连不上 / 其它状态码 分别给结论，设置面板显示的就是这句原文。模拟器上填这台反代加一把故意写错的 32 位 Key，状态行是「TMDB 拒绝了这把钥匙（HTTP 401）。反代只负责转发，API Key 仍要自己填；v4 Token 会以 Bearer 头发出。」路径已经打通，剩下的是钥匙本身。

反向代理输入框左边那个网络图标去掉了（`inputWithLeadingIcon` 一并删除），`Widgets.input()` 的文本统一左对齐，长 URL 不再被图标挤掉开头。

WebDAV 地址里显示成 `%E4%B8%AD%E6%96%87` 这种一串符号的目录名，是 URI 百分号编码没还原：服务器 PROPFIND 回来的 `<href>` 和保存下来的挂载路径都是编码过的。新增 `local/UrlLabels.displayPath()`，只对 `?` 之前的路径部分做按字节的 UTF-8 百分号解码（`+` 保持不动，非法的 `%zz` 原样留着，没有 `%` 就直接返回），登录框、已保存连接、局域网设备行、媒体源标题都改走它。它是个不依赖 Android 的纯函数类，因为 `SavedConnections` 不能去引用 `WebDavClient`——后者的编译单子里没有 kxml。

新增 `/tmp/pitest/run-tmdb.sh`（`TMDB_OK`）：起一个本地假 TMDB，断言 v3 Key 发出的请求路径是 `/tmdb0512/3/configuration?api_key=…`、v4 Token 带 `Authorization: Bearer` 且不带 `api_key`，再核对 404 / 401 / 空 Key 三种提示；`run-webdav.sh` 补了四条 `displayPath` 断言。第 3 条目前只有桌面级证据：模拟器上没挂中文目录名的 WebDAV，暂时截不到图。

## 遥控器手感、移除媒体源与筛选退场（1.17）

遥控器移动卡顿的实测结论：48 张海报的墙上走一圈，`dumpsys gfxinfo com.omniplay.tv` 是 402 帧 / 70 帧超标（17.41%）、68 次 `Slow issue draw commands`。三处成因——每次焦点变化新建一张 `GradientDrawable`（拿焦点、丢焦点各建一次，连带重算轮廓与阴影）、海报卡片叠了两层阴影（卡片一层、海报框一层）、缩放动画期间海报位图与两行标题每帧重新光栅化。`Theme` 现在把静止态与焦点态两张 drawable 一次画好缓存起来，`swapOnFocus()` 只换引用；海报卡只留卡片一层阴影（`elevation` 0dp→8dp，海报框恒为 0）；缩放动画期间挂 `LAYER_TYPE_HARDWARE`、结束摘掉；分集缩略图不再自带一套焦点样式，改与海报卡共用同一份缓存。同一套走位重测两遍是 412 帧 / 38 帧超标（9.22%）与 410 / 39（9.51%），`Slow UI thread` 归零，`Slow issue draw commands` 68→39。剩下的 9.5% 有地板：海报墙是不复用的 `GridLayout`（`Max resource usage: 99.53MB (x48)`），要再降得换 RecyclerView。

移除媒体源现在会连首页卡片一起清。`LocalEngine.removeSource()` 原先只改写媒体源列表，实体、文件、刮削队列都还留在 SQLite 里，首页照旧渲染那批海报。新增 `LocalMediaLibrary.purgeSource(sourceId)`：按 `local-<sourceId>:` 前缀挑出该源的文件（`LocalEngine.fileId` 的构造规则），删 `videoFile` / `offlineCache` 行与内存里的播放进度覆盖，再走新抽的 `pruneOrphanEntities()`——删掉没有任何文件的 `movie` / `tvShow`、这些剧的 `tvEpisode`、`sourceFileId` 指向已消失文件的 `scrapeQueue` 行。同一套剪枝也接到 `removeMissingFiles()` 后面，磁盘上删了影片重新扫描，卡片与空壳条目一起消失，与 mac 版一致。模拟器实测：本地源索引出 48 部时点「移除」，面板与首页同时变成「0 部」/「媒体库为空」，`待刮削 48 个条目` 一并清零。

筛选整块退场：右上角「筛选」按钮、类型与观看状态两组选项、`filteredItems()` 全删，首页名单只剩「按搜索词过滤 + 按当前排序排」。工具栏焦点行是 搜索 / 排序 / 降序 / 媒体源 / 设置，返回键少一个分支，计数文案用整个媒体库的条目数。

弹层滚动跟的是中线而不是边缘。原先 `scrollToVisible()` 判断「控件是否离开视口」，系统自己的 `requestChildRectangleOnScreen` 又把新获焦的行往视口边缘贴，两套逻辑打架：往上走时高亮在走、页面不动（约 8 次方向键的死区），而系统只会把第一个可聚焦控件对齐上边缘，标题与状态行永远回不来。`followVertically()` 现在只按布局坐标算落点：控件高于视口就露出顶部，否则中线对中线；第一行直接归零、最后一行到底（`scrollToEdge`）；行序仍由 `rowsFrom()` 按布局推导。设置面板的初始焦点从「主题第一颗色卡」换成 TMDB 卡片底部的「保存配置」——面板从顶部展开、焦点框一开始就可见，也不会顺手弹起软键盘。

「选择媒体目录」浏览器的操作行（选择此目录 / 返回上级 / 取消）从焦点顺序末尾提到第一行：影片目录动辄几十个子目录，原先要按几十次 DOWN 才够得着确认键；现在打开就在「选择此目录」上，往下进目录，往回一下回到按钮，进入子目录后焦点也重新落回它（SMB 共享根目录时它是禁用的，退回第一个目录行）。

## 选中态、媒体源抽屉与刮削队列（1.18）

焦点不再画框：`Theme.STROKE_FOCUS` 删掉，所有控件的边框粗细在静止态与聚焦态完全一样，聚焦改成「把控件自己的底色压深一档」（`Theme.darker(color, Theme.FOCUS_DARKEN)`）加原有的轻微放大与一层阴影，播放器里的半透明底板用 1.6 倍力度。海报是图片、压底色看不出来，所以海报框里预画了一张暗色遮罩，聚焦时 `bringToFront()` 显出来、失焦藏掉。类型选择、主题色卡、播放器菜单、详情页版本行上的对号全部撤掉，选中由配色表示（版本行改用「（当前）」文字）。

媒体源管理改成 mac 版那个添加抽屉：源卡片、「局域网设备（自动扫描）」（打开面板就自己扫，点设备直接登录或复用已存账号）、「添加 WebDAV 媒体源」/「添加 SMB 媒体源」两颗按钮。添加不再跳全屏设置页，弹的是居中卡片（显示名称 / 地址 / 用户名 / 密码 + 取消 / 手机输入 / 登录并选择目录），抽屉留在下面；选定目录挂载后只重绘抽屉与背后的海报墙，并在抽屉的状态行上跑扫描刮削。「重新扫描并刮削」变成首页工具条上的「扫描刮削」，与启动自动扫描共用 `startScanAndScrape()`：进度同时写抽屉状态行与首页顶部横幅，刮出一张海报就上墙一张，`scanRunning` 挡住并发。局域网扫描不再绑死在设置页上，宿主由 `lanScanTarget` 记录，`lanTargetAlive()` 判存活，动态插入的设备行按宿主重排方向键顺序。

「待刮削 274 / 275 来回跳、海报一张不出来」是两个问题叠在一起。`WebDavClient.relativePath()` 以前只在 `href` 原文以 `rootUrl` 开头时截相对路径，挂载点带中文时服务器回的是编码过的 `href`、前缀永不匹配，相对路径退化成最后一段编码过的文件名——刮削查询词、剧集分组名、播放地址三处一起坏；现在两边都先 `UrlLabels.displayPath()` 解码再比，入库一律存解码后的相对路径。刮削队列本身：入队改为按 `(mediaType, entityId)` 去重、取批只删取走的那几个 id（以前是 `DELETE FROM scrapeQueue` 整表清空，一批之外的条目直接丢）、计数改用同一套去重口径，`scrapePending()` 加锁单飞并循环取完所有批次（每批 200 条）。老库里的旧 fileId 会在下一次扫描被当缺失文件清掉后重新登记，属于自愈。

未刮削条目的名字照 mac 版重新提取（`LocalMediaNameParser`）：先按发布元信息截断（遇到 `1080p`/`x265`/`web-dl`/`s02e01`/`disc2` 这类词就砍掉后面全部），发布年同样按截断处理；中文片名取最长一组连续中文词并切掉「特典 / 花絮」之后的内容，外文片名按 mac 的噪声词表过滤；`displayTitle()` 依次尝试 中文片名 → 父目录中文名 → 外文片名 → 清洗后的整串，每层都过「这名字还能看吗」的体检（`movie`、`BDMV`、纯数字判不合格，《2012》放行）。电影用整条相对路径，剧集只用剧集目录名推导，保证同一部剧每一集算出同一个条目。海报下那行观看状态只剩图标：`○` 未看、`◐` 未看完、`✓` 已看，文字移到长按提示里。

## 源卡片行高、冷启动与刮削状态（1.19）

抽屉里的源卡片整块抬高：卡片加了 `Widgets.HEIGHT_ROW`（96dp）最小高度、内边距 10dp → 14dp，三颗按钮从硬写的 46dp 提到 `Widgets.HEIGHT_BUTTON`（56dp），「重新扫描」跟到 48dp。以前卡片高度全凭内容撑，WebDAV 源名只有一行时整块压成薄薄一条、按钮贴边上、「移除」经常点空；列表行、局域网设备行、已保存连接行也用同一个 `HEIGHT_ROW` 常量（78dp → 96dp）。WebDAV 源的默认名再补一次解码（`LocalEngine.defaultSourceName()` 也过 `UrlLabels.displayPath()`），首页卡片另加 `displaySourceName()` 兜一层，升级前就存进库里的 `%E7%94%B5%E5%BD%B1` 也能正常显示。

冷启动不再绕道设置页：`checkSession()` 删掉，有媒体源直接 `showHome()`，崩溃摘要改成一条 Toast——独立版没有服务端要问，那次 `authStatus` 往返只是多给网络抖动一次把首屏换掉的机会。左上角横幅换成 mac 版那套措辞与开关：`正在扫描媒体源...` → `扫描中 (2/3)：NAS-WebDAV` → `刮削元数据和海报 (12/248)：沙丘` → `扫描完成：新增 12，移除 3，共发现 248 个文件。`，收尾那条停 8 秒收起，空闲时整行不占位，常驻的「待刮削 N 个条目」取消；TMDB 没配好而队列非空时改说「检测到有待刮削的影视，但 TMDB 暂时无法连接…」。

「卡在待刮削 255、一半卡片名字没更新」是 `insertVideoFile` 的 `INSERT OR IGNORE` 与每轮重复 upsert 撞出来的：文件行还指着第一次入库那个实体，新算出来的实体没有文件、被 `pruneOrphanEntities()` 当空壳裁掉，队列里那批指向已删实体的行也再没人清。新增 `LocalMediaLibrary.bindEntityForFile()`——文件已有实体就复用，只在 `scraped = 0` 时改名；`pruneOrphanEntities()` 连带删掉这些队列行。`scrapePending()` 的排空循环从「不满一批就停」改成最多 100 轮，边扫边刮时扫描中途入队的那批不再被丢下。扫描入队还会跳过已刮到元数据的实体（详情页手动重新匹配走 `force = true`），整库不再每次冷启动重刮一遍。

卡顿这一版砍掉四处：逐条扫描进度改成按源报（255 个文件曾等于 255 次 `main.post` + 255 次横幅重写）、进度回调统一 250ms 节流、整墙重建防抖 2 秒、卡片渲染签名（标题 / 年份 / 观看进度 / 评分没变就跳过 `setText` 与重取海报）。模拟器（`-gpu host`）72 次方向键：135 帧、14 帧超期（10.37%）、`Slow UI thread` 0、没有一帧超过 20ms，PSS 60MB。剩下的地板还是那张不复用的 `GridLayout` 海报墙。

## 局域网设备行与扫描中移除媒体源（1.20）

局域网那一行点的是「去登录」。`connectDiscoveredDevice()` 以前有个捷径：`SavedConnections` 里存过上次挂载的目录就直接 `mountMediaSource()`，连登录框都不弹，用户想换共享目录根本没有入口。现在统一 `openLoginDialog()`（地址与账号回填）→「登录并选择目录」→ 目录浏览器 → 选定才挂载，与 mac 版 `openDiscoveredDeviceFromManageSheet()` 同一条路径。

行的格式照 mac 的 `discoveredDeviceTitle()`：探到设备名就用设备名，否则 `WebDAV 192.168.0.150`；端口不再掺进标题（同一台机器开 http / https 两个服务时，mac 上是标题相同、地址不同），第二行固定是探到的那条地址（WebDAV 解码后）。左边补了图标位：新增 `ui/KindIcons`，Canvas 画地球与机箱，22dp、取主题强调色，经 `Widgets.listRow(title, detail, leading)` 挂成 compound drawable，行的高度和焦点样式都没动。

移除媒体源后海报还挂在墙上，剩下的那半是时机问题：`scanAll()` 开头就把源列表快照进本轮，扫描进行中移除源，那一轮仍会把它的文件 `registerFile()` 回来，`removeMissingFiles()` 又把它们当「本轮扫到的」保留。现在 `LocalEngine` 维护 `liveSourceIds` 快照（`sources()` 与 `persistSources()` 时刷新），`registerFile()` 进门先问源还在不在；`scanAll()` 收尾再调 `LocalMediaLibrary.purgeUnknownSources(liveSourceIds)`，按 `videoFile.id` 里的源 id 清掉「源已经不在了」的文件行、离线缓存与进度覆盖，再裁空实体，数量并进「扫描完成：移除 N」。`purgeSource()` 与它共用 `deleteFileRows()`。

细节与验证记录见 [2026-10-09-android-tv-lan-row-login-first-scan-purge.md](2026-10-09-android-tv-lan-row-login-first-scan-purge.md)。

## 海报墙首屏、扫描按钮反馈与播放地址编码（1.21）

三个现象，两处代码。

**打开软件先看到全屏媒体源页，挂完源又卡在「正在扫描媒体源」。** 首屏那个分支是 `onCreate` 里 `api.hasServerUrl()` 的判断，而独立版这句话等价于「媒体源列表非空」——库里一个源都没有时就被判成「还没配好」，整屏设置页盖在海报墙前面。挂载路径上另有一处 `showLoading("正在扫描媒体源")`：几百个文件的 WebDAV 能在那一屏停几分钟，一张海报都看不到。现在 `onCreate` 无条件 `showHome()`（崩溃摘要仍是右上角一条 Toast），空库时由 `emptySourceCallToAction()` 在墙上给一颗「添加媒体源」直接开抽屉；`mountMediaSource()` 挂完就 `showHome()` + `startScanAndScrape(null)`，与 mac 版一样立刻回墙、后台扫刮、海报逐张上墙，失败只 Toast 不挡路。抽屉里补了第三颗「添加本地目录」（与另两颗同高），因为全屏设置页退场后那是唯一入口；已保存连接的补录也随抽屉渲染一起跑。

**点右上角「扫描刮削」没反应。** 两个原因叠在一起：一是 `scanRunning` 为真时那句 `return` 静默无声；二是上一轮的收尾文案与这一轮的开场文案一模一样（都是 `正在扫描媒体源...`），横幅的「同一句话不重复显示」机制 `homeStatusHiddenMessage` 把它压住了，看起来就是按了没反应。现在点下去要么 Toast「扫描刮削正在进行中，海报会陆续出现在首页。」并把横幅重新显示，要么立刻把横幅写成 `正在扫描媒体源...`、按钮换成「扫描中」，两轮回调各自复位按钮；`startStartupSync()` 也改调同一个 `startScanAndScrape(null)`，不会再有两轮扫描抢同一批文件。

**点海报抛 `No static method encode(Ljava/lang/String;Ljava/nio/charset/Charset;)`。** `URLEncoder.encode(String, Charset)` 是 Android 13（API 33）才加的重载：编译时用 android-35 的 `android.jar` 过得去，`minSdk` 26 的机器上运行时找不到方法直接 `NoSuchMethodError`。`WebDavClient.streamUrl()` 是唯一一处（全库扫过 `readAllBytes` / `transferTo` / `Path.of` / `Files.*` / `List.of` / `isBlank` / `URLDecoder.decode(..., Charset)` 这些同类陷阱，没有第二处），换成字符串重载 `URLEncoder.encode(value, "UTF-8")`。顺带把 userinfo 里的空格从 `+` 改成 `%20`——`+` 只在 query 里代表空格，路径与账号里不行。

细节与验证记录见 [2026-10-10-android-tv-wall-first-boot-urlencoder-api.md](2026-10-10-android-tv-wall-first-boot-urlencoder-api.md)。

## 刮削结果回海报墙 + 详情页手动匹配 / 自定义编辑（1.22）

**详情页显示已刮削、海报墙还是老样子。** 首页渲染用的是内存里那份 `libraryItems`：刮削在后台跑，进度回调带动的补卡片有两条前提——人在首页、且距上次补卡超过两秒。用户点进详情页看结果时，这两条都不成立，那一轮的补卡结果被直接丢弃；而从详情页返回首页时 `showHome()` 只重绘、不再重读媒体库（为了避免多一次加载态），拿的还是刮削开始前那版名单。详情页每次现查数据库，于是就成了「详情页已经刮好，首页还是占位字母」。改法是把「回首页」当成一次真正的重新同步：`showHome()` 里补一个 `refreshLibraryInPlace()`，从数据库重读一遍再就地补卡片，条目没变的卡片仍由渲染签名跳过重绘。

顺带修掉一个同族问题：`patchLibraryViews()` 以前只比新旧两次读取的**条目数量**，数量相同就当「还是那批条目」。清库重扫、或者手动匹配跨类型改绑（电影 ↔ 剧集会换表重建实体、条目 id 跟着变）时数量正好一样，于是每张卡都按旧 id 找不到新数据，整面墙原地不动。现在比的是 id 集合。

**详情页「手动匹配」。** 照 mac 版 `MovieSearchModalView` 的遥控器版：显示源文件路径、关键词（预填当前片名）、年份，打开即搜一次；候选清单按 mac 那套打分排序（`TmdbClient.searchCandidates()`，与自动刮削同一份取数与打分逻辑，只是不取最高分那一个），每行显示片名 / 年份 / 类型 / 简介，点一行就关联。关联走 `LocalEngine.bindToTmdbResult()`：写进实体、按 `append_to_response=credits` 补齐导演主演（名单已有内容就不覆盖，可能是用户手填的）、并置 `isLocked`；类型不匹配时换一张表重建实体、文件行跟着搬走，详情页整页重开。

**详情页「自定义编辑」。** 对应 mac 版手动编辑资料的「保存修改并锁定」：片名、上映日期、TMDB 评分、类型、导演、主演都能手填，名单用顿号或逗号分隔、入库统一转成竖线；六个字段都能用「手机输入」传。保存即锁定。

锁定终于开始生效：`isLocked` 这一列以前只写不读，现在刮削队列取到已锁定的条目就直接跳过（队列行在取批次时已经删掉，不会卡在「待刮削」上），mac 版同样如此。手动重刮（`requeueScrape()`）会先解锁——用户主动要求重刮，要的就是新结果。

细节与验证记录见 [2026-10-10-android-tv-wall-refresh-manual-match-edit.md](2026-10-10-android-tv-wall-refresh-manual-match-edit.md)。

## 首页头部改版（符号图标 + 左上角进度行）与刮削队列补漏（1.23）

**左上角不再有「觅影 OmniPlay」。** mac 版首页左上角那一格从来不是品牌位，而是扫描刮削进度：一个小转圈加一行状态（`Scraping metadata and posters (n/m): …`）。现在照它做：`homeProgressRow` 占住工具栏左边的整条空位，`homeStatusView` 显示进度，`homeProgressView` 是 17dp 的转圈。原来挂在工具栏下方的那条横幅撤掉了，两处显示一份状态。

**六颗按钮改成符号。** 新建 `ui/Icons.java`，用 `Canvas` 在 24 单位网格上画 mac 版对应的 SF Symbols（`SEARCH` 放大镜、`CHEVRONS` 上下菱形、`ARROW_UP`/`ARROW_DOWN` 升降序、`SYNC` 环形箭头、`FOLDER_PLUS` 带加号的文件夹、`GEAR` 齿轮、`SPINNER` 缺口圆环，以及海报卡右下角的 `WATCH_NONE`/`WATCH_PART`/`WATCH_DONE`）。`Widgets.iconButton()` 造出来的 `ImageView` 只画图标，名字走 `contentDescription` 与 `tooltipText`（长按/焦点提示能看到「扫描刮削（进行中）」这类现词）。海报卡右下角的已看状态也从文字（`已看`/`未看完`/`未看`）换成同一套图标。

**选中态去掉颜色加深。** `Theme.FOCUS_DARKEN` 归零，焦点语言只剩三样：轻微放大（`FOCUS_SCALE`）、抬升阴影、强调色描边，图标本身染成强调色。以前聚焦会把填充压暗一档，在深色主题上和「按下」几乎同义，遥控器用户分不清是选中还是按住了。

**「正在扫描中」却一张新海报都没有。** 根因在 `LocalEngine.registerFile()`：入队刮削被写在「文件名解析出中文名或外文名」这个条件里，`queueScrape()` 现在改成先用解析结果、解析不出就拿展示标题兜底，只要标题非空就入队。之前那批卡片（文件名没有结构化信息的样本，如 `Film 02`）从来没进过队列，扫描照样跑完、进度照样走完，只是刮削队列是空的——按钮上的「正在扫描中」是真的，只是无事可做。

同时把收尾文案改成会说实话：`刮削完成，共处理 N 个条目：X 个请求失败，Y 个没搜到，Z 个年份对不上，跳过 S 个手动匹配的条目。`（没有异常时是「全部更新」。）以前只报一个总数，用户没法区分「没跑」和「跑了但没搜到」，而这两种情况该做的事完全相反。

转圈动画跟着真实状态走：横幅在跑完还要停 8 秒才收起，这期间没有活要干，转圈就一起藏掉（`setHomeStatusVisible()` 里按 `scanRunning` 决定），进度回调每 250ms 一次也不再把动画按回零点。横幅收起用 `INVISIBLE` 不是 `GONE`——那一格占着工具栏左边的权重，收成 `GONE` 会让六颗按钮整体左移，焦点跟着跳到别的按钮上。

**验证（模拟器 + 假 TMDB）。** 冷启动后左上角依次出现 `正在扫描媒体源…` → `刮削元数据和海报 (19/42)：Film…` → `刮削完成，共处理 42 个条目：42 个年份对不上。`，42 个条目正是上一版从没入过队的那批；假 TMDB 日志收到 89 条 `/search/multi`，说明请求真的发出去了（年份对不上是假服务器对所有查询都回同一条 2021 年的结果）。工具栏图标、焦点态（放大 + 强调色描边、无加深）、已看图标、设置弹层输入框焦点都逐项截图核对。

## 图标对齐 mac + 刮削真的实时在跑（1.24）

**符号形状照 mac 重画。** `ui/Icons.java` 里每个符号都改成 mac 版对应 SF Symbol 的画法：排序从「上下 V」换成 `line.3.horizontal.decrease.circle`（圆里三条左对齐、逐条变短）；升降序换成 `arrow.up` / `arrow.down`（通高箭杆 + 45° 箭头，不再是两根 V）；扫描刮削的 `arrow.triangle.2.circlepath` 改成两段 150° 弧各自带**沿切线方向**的箭头（此前箭头是钉在固定坐标上的，弧一动就散架）；媒体源换成 `folder.badge.plus`（加号徽标先用 `CLEAR` 在文件夹线上挖个洞再画，否则加号和底边糊成一团）；设置换成 `gearshape`（齿圈 + 本体 + 中心孔，不再是「太阳光」）。

**平时没有底板。** 1.23 那版给每颗按钮留了玻璃底板，mac 版这排是 `.plain`：底板在 TV 上把工具栏挤成六个方块，反而不像 mac。现在 rest 态完全透明，图标颜色也按 mac 的 `textPrimary.opacity(0.78)` 调亮（原来用的是弱化文字色，三米外看电视基本是灰的），进度文字同样从 `COLOR_SUBTLE` 提到主文字色 86%。

**左上角那一行现在只要还有活就没走。** 显示条件改成 mac 那条：`扫描中 || 引擎在刮削 || 队列里还有条目`。收尾文案仍然停 8 秒，但只要队列没见底（比如一轮里全是失败）就一直留着，并写清原因；空转时新增一条「待刮削 N 个条目，点右上角「扫描刮削」开始。」。以前的行为是收尾停 8 秒一律收起，用户过一会儿回到首页，只看得到一面不动的墙，完全不知道发生了什么。

**刮削队列现在会自愈。** 这是「海报墙长时间不更新」的根因。TV 版的刮削队列是一张表，取批次时按行删掉，请求失败一次的条目就此离开队列，而扫描只给**新登记**的文件入队——于是这些条目以后再也不会被刮，海报永远停在占位字母上，界面上一点线索都没有。mac 版没这个坑：它每轮都从库里现算未刮削清单（`processUnmatchedFiles(sourceID:)`），失败的条目下一轮自然再试一次。现在 `LocalMediaLibrary.requeueUnscraped()` 在每轮刮削开始前把「`scraped = 0` 且没被手动锁定」的实体重新排进队列，两边行为对齐；网络抖一次不再等于这批片子永久放弃。

**刮削前先探测连通性。** 以前只要填了 Key 就闷头往下刮，TMDB 不通时几百个请求全打在超时上，进度条走完了才发现一句「请求失败」。现在照 mac 的「检测 TMDB 连通性...」先探一次 `GET /3/configuration`（5 分钟内成功过就不重复探，`PROBE_REUSE_MS`），探失败就**不取队列行**直接返回，状态行写「TMDB 无法访问：<原因>」，条目整整齐齐留在队列里等下一轮。

**海报走 CDN 失败时改走反代。** `ImageLoader.load()` 多了一个 `fallbackUrl`：官方 `https://image.tmdb.org/t/p/...` 取不到东西时，再试一次同一台反代的 `/t/p/...`（Worker 类反代通常一起转发图片路径），成功的图按正地址入缓存，所以每张图一生最多只多花一次失败请求。没配反代时这个参数是 null，行为与以前完全一致。

**海报补得快一档。** 就地补卡的节流从 2 秒降到 700ms（`WALL_PATCH_INTERVAL_MS`）。两秒是当年为了躲整墙重排留下的，就地补卡早就不重排了；进度回调本身已经限到 250ms，这里再低只是白跑查询。

**验证。** 模拟器 + 假 TMDB（每次搜索拖 0.6 秒、海报由假服务器自己发图）。启动后左上角依次是 `检测 TMDB 连通性...` → `刮削元数据和海报 (13/42)：Film` → `(37/42)` → `刮削完成，共处理 42 个条目，全部更新。`；同一段时间里海报墙从「六张占位字母」逐张变成带海报、带评分的卡片（截图序列 `v24-d/e/f/g`），确认是一条条实时补上而不是跑完一轮一起变。假服务器日志确认每个条目两次请求（`/3/search/multi` 与 `/3/movie/{id}?append_to_response=credits`），海报请求走的是 `…/tmdb/t/p/w500/…`，即反代兜底那条路。

细节与验证记录见 [2026-10-11-android-tv-mac-symbols-live-scrape-selfhealing-queue.md](2026-10-11-android-tv-mac-symbols-live-scrape-selfhealing-queue.md)。

## 扫描进度不再冻结、移除媒体源立刻清场（1.25）

**扫描阶段自己也报进度。** 上一版左上角那行“只要还在干活就在”，但干的是扫描时它一整天只显示「正在扫描媒体源...」：扫描进度只走回调、不落 `scrapeStatus`，而首页读的就是后者。现在 `LocalEngine` 里所有进度都从同一个 `progress()` 出，顺手补上 mac 那套句子——`扫描目录中...` → `扫描中 (i/n)：源名 · 已发现 N 个文件`（`ScanCollector` 每 400ms 重播一次计数，几百个文件也不会一秒刷一条）→ `完成：源名（新增 N）` → `更新首页...` → `扫描完成：新增 X，移除 Y，共发现 Z 个文件。`

**扫描或刮削正中间移除媒体源，不再留一张幽灵卡片。** 以前收尾清理只在整轮结束时跑一次，而手上那个目录树还在往下走：被移除的源照样把文件登记回库，等清理跑完，用户看到的还是“移除之后又冒出来的未刮削卡片”。现在 `ScanCollector.register()` 每次登记前先看源还在不在不在就抛 `ScanAborted`（`SmbClient.walk()` 原样透传，不吞成“翻译后的错误”），当轮立刻收手，收尾的 `purgeUnknownSources(活着的源)` 负责把尾巴清干净，横幅写「已移除：源名，本轮跳过」。同时首页加了 `libraryFetchSeq`：并发发起的媒体库读取只认最后一次结果，避免慢的那条把新库覆盖回旧库。

**首屏不会卡在「正在加载媒体库」。** `showHome()` 以前同时发两条读取（整页读 + 就地补丁），补丁那条号大、赢，而它只往已有的卡片上刷东西——库是空的就什么都不做，于是首页永远停在中间那行 loading。现在一次只发一条：墙上有卡片才补丁，否则走整页读取（空库照常渲染成「还没有媒体源」的空状态）。

**屏幕上不再甩一大段异常。** 三处一起收：worker 回调里抛出的异常只写日志和 `CrashLog`，不再 `Toast`；上次崩溃的提示从整份报告（十几行 `at ...` 栈）换成一句「上次运行异常退出（已记入日志）」；`showToast()` 统一走 `briefMessage()`——压掉换行、截到 96 字、改 `LENGTH_SHORT`，WebDAV 那种整段 XML 错误体再也糊不到屏幕中间。扫描失败那条也改用 `CrashLog.summarize()`，输出是一行「类名：原因（方法:行号）」。

**两颗按钮重画。** `folder.badge.plus` 的加号徽标从右下角挪到右上角、改成实心圆里 `CLEAR` 挖出加号（此前加号压在文件夹底边上，远看像个对勾）；`gearshape` 的齿圈加粗 1.5 倍、八颗齿改成从齿圈向外伸的胶囊、中心孔收小，设置那一眼终于认出是个齿轮。

**验证。** 模拟器上造了 252 个文件（`Movies` 12 个 + `Bulk` 240 个）重新挂载：启动直接进海报墙；挂载后 3 秒左上角是 `刮削元数据和海报 (1/295)：Film`，抽屉里同步显示 `扫描中 (1/1)：源名 · 已发现 297 个文件`，12 秒后走到 `(14/295)`，卡片随进度一张张从占位字母变成带评分的海报；刮到 `(215/295)` 时点「移除」，首页立刻回到 0 部的空状态，此后 15 秒内没有再冒出任何旧卡片，横幅也没有赖在「正在扫描媒体源」上。截图序列 `v25-mid0/1/3`、`v25-ab1/2/3`、`v25-m1/m2`。

## 详情页收进长按、海报改走反代（1.26）

**媒体源抽屉瘦身。** 抽屉里那行进度和首页左上角是同一句话，两处各写一份只会让人来回找，现在进度只写首页那一行（挂载之后 `startScanAndScrape(null)` 不再往抽屉回写）。`停用后该目录不再扫描入库…` 这句说明删了。重命名也不再弹一整屏：点「重命名」就在这一行正下方长出一个输入框加「保存」，写完就地收起，焦点不用从头找一遍。

**选目录加了一颗星。** 以前要点进文件夹才能挂载，想挂的是上级就得进进出出。现在每一行右边一颗星：点名字进下一级，点星直接挂这一级（`Icons.Kind.STAR`，已挂载的那颗是 `star.fill` 加「已挂载」）。

**详情页收成一行动作。** 第一行是 `开始播放` + 已看状态图标 + 播放进度条，进度条从按钮底下挪到图标右边，「能不能播、看到哪儿了」一眼看完。已看状态用 mac 那三个符号（`checkmark.circle.fill` / `circle.lefthalf.filled` / `circle`），只留图标，状态名进 tooltip。`手动匹配` 与 `自定义编辑` 从页面上撤下来，改成在播放按钮或已看图标上长按确认键，弹出「刮削与资料」小面板二选一。这里有个坑：遥控器 OK 键送来的是 `KeyEvent`，`View` 自带的长按回调只在手指触摸时才触发，`attachDetailLongPress()` 自己起计时器，按住超过 `ViewConfiguration.getLongPressTimeout()` 就弹面板，松手那一下吃掉，不再顺带触发一次播放。

**手动匹配与自定义编辑都能挑海报。** 候选结果从一行文字变成「小海报 + 片名 + 一句话说明」（`posterRow()`）。自定义编辑底部加了一块海报：当前海报缩略图 + `手机推送海报`（沿用局域网那套手机填表服务，手机上贴一个图片地址推回来）+ `从 TMDB 选海报`（列出前六张候选）+ `恢复自动海报`。写库走新加的 `LocalMediaLibrary.setPosterOverride()`，只动 `posterUrl` 和 `isLocked`，不碰别的资料。

**三处按 mac 收。** `版本 / 文件（N）` 只在同一部片真刮到多于一个文件时才出现（`files.size() <= 1` 直接返回，对齐 mac 的 `videoFiles.count > 1`）；首页海报下的片名改居中（mac 是 `multilineTextAlignment(.center)`）；分集剧照下面的「改副标题」输入框删掉。

**「已发现 N」一直涨、「N 部」不涨。** 三处叠出来的：① 上一版的「只认最后一次读取」在扫描期是反效果——进度每 400ms 重播一次就会再发一次整库读取，只要有一条比这个间隔慢，所有结果都在落地前被后来的顶掉，界面永远停在旧数字上；② `libraryItems()` 是 N+1 查询，每个实体单独查一遍自己的文件；③ SQLite 还在用回滚日志，扫描写的时候读会被挡。现在进度行上的那个数直接问数据库（`entityCount()`，一条 `SELECT COUNT(*)`），`libraryItems()` 改走一次 `allFilesGrouped()` 批量分组，首页刷新改成单飞加尾随重读（`requestLibraryFetch()`：正在读就记一次「读完再补一轮」，不再叠三条），`onConfigure()` 里开 WAL，读写不再互相堵。

**海报原来一直在官方 CDN 上空跑。** 用户报「海报墙长时间不更新」，模拟器里加日志才看清：每张海报都先请求 `https://image.tmdb.org/t/p/w500/…`，配了反代时这一趟基本是 404 或超时，回头才试反代的 `/t/p/`。一屏四十几张卡排队、四个线程，一轮就是几十秒，看上去就是「刮完了海报还没出来」。现在 `TmdbClient.posterImageUrl()` 在配了反代时把海报地址直接改写到反代的 `/t/p/` 上，官方 CDN 退成备胎（`posterFallbackUrl()` 两个方向互转），库里存的仍是官方地址，哪天不配反代照样能用。

**验证。** 模拟器 + 假 TMDB（反代指向 `http://10.0.2.2:8099/tmdb`）：新增 60 个文件重启后，左上角 `刮削元数据和海报 (26/60)：NewTitle26` → `(39/60)`，`所有影视 238 部` 一路上涨没有冻结，满屏彩色海报正常上墙（`v26-m-home`、`v26-o-22`），`OmniPlayPoster` 日志里的 CDN 404 全部消失；抽屉里每行一颗星、没有进度行、重命名内联展开（`v26-c-picker`、`v26-d-rename`）；长按播放键弹出「刮削与资料」（`v26-k-sheet`）；手动匹配候选带小海报（`v26-n-match`）；自定义编辑的海报块三个按钮齐全（`v26-n-edit`）；详情页第一行只有播放 + 图标 + 进度条，`版本 / 文件（2）` 只在真有两个文件的那条上出现（`v26-k-detail`）。

## 停用真的收起海报、扫描只扫新增（1.27）

**停用媒体源＝从首页收起来。** 以前点「停用」只是把源从下一轮扫描里剔出去，首页海报一张不少，得等哪一轮扫描把它当「盘上没了」删掉才消失。现在媒体库的两条读路径（首页列表与那颗计数）都带上启用源过滤，与 mac 版每条查询都写 `COALESCE(mediaSource.isEnabled, 1) = 1` 同一条规则：停用的源立刻从墙上消失，重新启用立刻原样回来，数据一行没动，也不需要重新扫描。扫描收尾的「这轮没再见到就删」也只在这一轮真扫过的源里做，否则停用源的文件会被误删。有个坑值得记：过滤条件用空集合表示「一个都不算」，早期实现把空集合当成“不加条件”，于是**全部源都停用**时首页反而满墙海报。全停用时空墙给一句人话（「媒体源都已停用，海报先收起来了」）加一颗「添加媒体源」，别留一块没有任何可聚焦控件的空白。

**扫描只扫新增。** 以前每扫一次，扫到的每个文件都重走一遍完整入库：重绑实体、重插文件行、重填刮削队列（每次先 DELETE 再 SELECT 判重）。一万条记录就是三万次写，扫描十几分钟跑不完，而刮削排在扫描后面，于是「已发现文件一直涨、刮削一直没开始」。现在每个源开扫前先读一遍它已入库的相对路径，扫到的路径只要认识就只做一次集合查询：不重绑、不重插、不入队；不认识的才走完整入库。第二遍扫描因此变成「共扫描 62 个文件，新增 0」，几秒收工。进度句也跟着改准：`扫描中 (1/2)：源名 · 已扫描 N 个文件，新增 M`，收尾是 `扫描完成：新增 X，移除 Y，共扫描 Z 个文件。`「已发现」这个词以前把两种数混在一起，看着就像扫描停不下来。

**登录弹窗抢回焦点。** 抽屉里点局域网设备弹登录框，焦点有概率还留在抽屉里，登录框怎么走都走不进去。原因是弹窗的重声明 `Overlay.focus()` 无条件 `replaceTop`：局域网扫描每发现一个设备就重声明一次抽屉的方向键行，而这时候活动网格已经属于上面那层登录框，等于把登录框的网格整个换成了抽屉的。现在重声明先看自己是不是最上面一层：不是就先记账（`staleRows`），等上面那层关掉、自己被顶上来时再补链接。

**详情页两颗工具。** 上一版的长按二级面板撤掉，改成详情页右上角两颗图标：`text.magnifyingglass`（手动匹配）与 `pencil`（自定义编辑），都是 Canvas 画的矢量符号，方向键往右上两步就到。

**验证。** 模拟器全程遥控器（不用触摸）：单源停用后首页立刻 `所有影视 0 部` + 「媒体源都已停用」空状态；点「启用」原样回到 60 部，期间没有重扫。抽屉里打开「登录 SMB」，等局域网扫描收尾（它必然重声明抽屉的焦点行）后焦点仍在登录框内，方向键照常走。第二次点「扫描刮削」左上角写 `扫描完成：新增 0，移除 0，共扫描 62 个文件。（蓝光非正片分卷跳过 2 条）`，几秒返回。详情页右上角两颗图标分别打开手动匹配（候选带海报）与自定义编辑（含海报三颗按钮）。

## WebDAV 遍历走出指数量、扫描途中就出海报（1.28）

**遍历原地自套才是「扫不完」的真凶。** Depth:1 的 PROPFIND 按 RFC 4918 必须把「本次被请求的那个目录自己」也算作一条响应。旧 walker 是深度优先、只按层数收敛（`maxDepth = 12`），照着单子递归下去就是每个目录重新进自己一次、里面每个文件重新报一遍，n 层目录是 12 的 n 次方级别的重复。真机上「已扫描 169990 个文件、新增 0」就是这么来的，而且清单缓存被编码写法不同、结尾斜杠不同的同一目录反复撑大，几分钟后进程就没了。改成 mac 版那一套（`scanFiles(in:)` 的 `pendingDirectories` + `visitedDirectories`）：广度优先、目录身份按**解码后的路径**算（编码写法与结尾斜杠不同算同一个目录）、再单独跳过响应里指向本目录自己的那条。深度这条只当兜底。另加两道底线：一轮最多列 20000 个目录、清单缓存最多 4096 条，再畸形的响应最多让这一轮少扫一片，不会把电视跑死。SMB 同步从递归改成 BFS + visited（SMB 路径不区分大小写，比对前折叠）。

**「已扫描」和「新增」各管各的账。** 采集器现在带两份名单：`knownPaths`（上一轮就入库的，只用来决定要不要重新入库）与 `seenThisRound`（本轮已经数过的，只用来挡重复条目）。合成一份会踩两个坑，都在这轮真机上撞到了：已入库的文件被当重复挡在记账之前，收尾的「这轮没再见到就删」就把整面墙删掉（210 部扫成 10 部）；反过来把计数放在判重之后，第二遍扫描就成了「共扫描 0 个文件」。现在 `fileIds` 在每条出口之前先记，`已扫描 = 盘上真有多少个文件`，`新增 = 其中第一次入库的`。

**扫描途中就开始刮削。** 刮削以前严格排在整轮扫描之后：WebDAV 走不完，255 个待刮削条目就一直不动，只有点进海报再返回才刮那一条。现在每登记 20 条新文件就从扫描线程借 4 秒刮一批（`pumpScrapeDuringScan`），每个源扫完再刮一轮，收尾照旧是一次不限时的 `scrapePending` 兜住剩下的。借出来的时间用截止时间卡住，用完就把队列留给后面几轮——那些条目仍是未刮削、还会被下一轮开头的补队列捞回来，一条都不会漏。mac 版是每个源扫完就 `loadData()` 刷首页再刮，方向一致。

**扫描到一半被踢回电视主页。** 遍历空转那几分钟把内存搅得很干净地坏了：`ImageLoader` 的解码任务只 `catch (Exception)`，一条 `OutOfMemoryError` 从线程池逃出去就带走整个进程，而崩溃摘要被压成一行短句，用户看到的只是「过几分钟自己退出」。现在解码任务接住 `Throwable`（一张海报换一条日志，不再换整个应用），清单缓存加上限，`AndroidManifest` 开 `largeHeap`（海报墙一轮要摆几百张图）。

**验证。** 假 WebDAV（`/tmp/fakewdav.py`：17 个目录 / 240 个文件，每条 PROPFIND 响应都带上「目录自己」那一条，与 nginx、Apache、Nextcloud 同一种行为）+ 假 TMDB 走完整挂载流程：冷启动第一轮服务端只收到 16 条 PROPFIND、每条恰好一次（旧版这里是指数量）；扫描正中间左上角就写 `刮削元数据和海报 (4/35)：Movie024`，海报一张张上色，`所有影视` 从 41 → 190 → 210 部一路上涨；第二遍扫描 `扫描完成：新增 0，移除 0，共扫描 239 个文件。`，海报墙一张没少。

细节与验证记录见 [2026-10-12-android-tv-webdav-bfs-visited-scrape-during-scan.md](2026-10-12-android-tv-webdav-bfs-visited-scrape-during-scan.md)。

## 外文片名换中文译名、年份按 mac 重取、八套主题重画（1.29）

**外文片名换中文译名。** TMDB 在缺少中文条目时会直接把原文名当 `title` 回传，刮削结果里就留下 `Inception`、`Christopher Nolan` 这类外文名，首页和详情页跟着一起变英文。这一版补上 mac 版 `ChineseNameStore` 那条链路：刮到资料后顺手问一次 `/{movie|tv}/{id}/alternative_titles`，电影别名在 `titles`、剧集在 `results`，先认 CN / SG / TW / HK 四个地区的译名，都没有就退到任意一条含汉字的别名（`TmdbClient.fetchChineseTitle()`）。查到就只改标题、**不动 `isLocked`**——手动匹配过的条目照样该显示中文片名，「锁定」挡的是自动刮削覆盖。查询结果连同「TMDB 确实没有中文条目」一起记进新表 `chineseNameCache`（正缓存一直用，负缓存 30 天），只有请求失败才留到下一轮重试；刮削收尾再从库里挑最多 40 条「已刮削、片名没汉字、别名没查过」的条目补一遍，老库里那些早就刮成英文的条目也有机会翻过来。刮削语言选成 English 时整套逻辑跳过，英文界面就该留原文名。

**表是加了，老库里却没有。** `onCreate` 只在数据库第一次建立时跑，`onUpgrade` 只在版本号变化时跑，而两处都会走的那句 `onCreate(db)` 也就跟着不会跑。新表就这么在装过旧版本的机器上凭空少了一张，第一次查缓存就抛 `no such table`，被刮削循环的 `catch` 吞掉后整条条目记成「请求失败」——表现是刮得动、海报也出，就是不换中文名。数据库版本号提到 3。

**年份按 mac 的取法重来。** 上一版取的是「文件名里最大的那个四位数」，`Toy.Story.1995.2010.720p` 记成 2010、按年份建的目录（`2024/某片.2019.mkv`）记成 2024——片名自带的年份永远抢不过后面那些重制与发行年份，年份校验于是把对的匹配一批批判死。现在照 mac 的 `chooseReleaseYear(from:)`：取**第一个**前后不接数字的 1900–2099，只有一种例外——文件名开头就是第一个候选（`2012.2009.1080p.mkv` 这种片名本身是个年份的），年份取第二个。十组用例逐条对过（含 `Blade.Runner.2049.2017` → 2049、`2001.A.Space.Odyssey.1968` → 1968）。改的时候踩了一处：年份正则只有一个捕获组，按两组取值就是 `IndexOutOfBoundsException`，而它从入库那一层往外抛，整轮扫描直接以「扫描失败：null」收场，界面上只是海报没动静。

**八套主题重画。** 浅色五套原本把 mac 的色值原样搬过来，投影仪和电视上看就是一屏发灰：纯白卡片贴在纯白底上分不出层，副标题灰得读不清。这轮每套都重调了底色 / 卡片色 / 两级文字色 / 强调色，并各自多带一个 `wash`：背景渐变从左上「底色掺 wash」走到中间纯底色，右下角再让强调色显出来（`Theme.appBackground()`），四段停靠点让中间一大段保持纯底色、整屏不发灰。副文字统一压深到 4.5:1 以上，海报墙滚起来时卡片标题在三米外还读得完。设置里那颗小色块也从「一块卡片色 + 一条强调色」换成迷你页面缩影（背景渐变 + 一张卡片 + 一条强调色），八套摆在一起能直接看出差别。

**详情页与弹窗两处收拢。** 简介不再按 96 字折叠：电视上一屏就放得下，多一颗「展开简介」只是多一颗要按的按钮。手动匹配弹层里那句「找到 N 条结果，点一行关联到这条影视。」撤掉——候选清单自己会说话，省下来的高度正好多摆一条候选。右上角 `text.magnifyingglass` 重画：三行长短递降的文字压在左上、放大镜落在右下，圆周先在独立图层上抠掉一圈再画镜筒（与 `watched` 图标同一手法），22dp 下笔画不粘连。

**验证。** 模拟器 + 假 WebDAV（17 个目录、根目录与子目录各摆若干文件、蓝光目录）+ 假 TMDB（搜索按查询词回外文库名、`alternative_titles` 回一条 CN 别名）：走完整挂载流程后 `扫描完成` 登记 7 个文件，海报墙先出外文库名，刮完变 `中文译名1048` 这样的中文名，第二轮扫描不再多发一次别名请求（正缓存挡住）；假服务器只回 2010 年的结果，`Toy.Story.1995.2010` 按 1995 判为年份对不上、`Inception (2010)` 正常通过，正是 mac 那套取法该有的结果。详情页简介整段显示、右上角两颗图标重画后放大截图核对；八套主题逐一点过，深色两套在关灯截图里对比正常。

## 开软件就是海报、一部剧只留一张、名称年份按 mac 现算（1.30）

**已刮削的海报开软件那一下就该在屏上。** 以前冷启动整面墙第一次加载全部走「先占位字母、再异步解码」，内存缓存又挂在 `ImageView` 与面板上，于是一屏白卡片过一会儿才补齐。现在内存缓存提到进程级 `LruCache`，取图成功时顺手把 1.3 倍尺寸、JPEG 82 质量的缩略图写进 `<cacheDir>/image-loader/`，已刮削条目的第一次加载改成本线程同步解码这张缩略图直接铺上（不经过占位图）；同步解码有一道 14MB / 滚动一秒的预算，超了就退回异步，首帧不会把遥控器手感拖成卡顿。老缓存里只有整图的，命中整图时补一张缩略图，越用越快。

**同一部剧不能挂两张一样的海报。** mac 版的作品表以 TMDB id 当主键，结构上不可能重复；TV 版实体 id 是自增的，`流人.Slow.Horses.2022.S01.../` 与 `Slow.Horses.S02.2023.../` 各自建一条 `tvShow`，刮到同一个 TMDB 作品也只能并排摆两张同样的海报。新增 `collapseDuplicateWorks()`：按 `tmdbId` 找重复，留下刚刷到资料的那条（不在场就留挂着文件多的那条，播放进度不丢），文件行、剧集分集行、队列行一并搬过去再删败者。挂在自动刮削写完结果后、手动匹配关联后、以及每轮收尾对整库扫一次——老库升级后点一次「扫描刮削」就自愈。

**刮的是快照，不是文件。** 这一版之前 TV 版用的是队列里存的那份快照：`query` 是实体标题、`year` 取自已有的上映日期（未刮削的行根本是空串）、只发一次 `search/multi`。年份加权因此全盘失效，同名作品由热度决定生死，《偷自行车的人》输给了 2026 年的同名新作；中文目录名只对上一部不相干华语片时也没有第二条关键词可降级，《流人》就成了《接住流星的人》。现在刮前先取该实体的代表文件，用 `combinedSearchMetadata(relativePath, fileName)` 现算片名与年份，再走 mac 那五级降级：中文片名 → 父目录中文 → 外文名（含 `A.K.A.` 拆分）→ 完整清洗名 → 去空格去数字。每个关键词查两种语言、各取两页；`normalizeTitle` 丢光非字母数字（`Slow.Horses` 与 `Slow Horses` 算同一个），年份分照 mac 的 `calculateScore`，剧集按**那一季的首播年份**比（`/tv/{id}/season/{n}`，带负缓存）。另加一道相关度门槛：最高分那条连标题相关性都不过线就当没搜到，交给下一级关键词；手动匹配的候选列表不受这条限制。年份校验容差从 2 年收到 1 年，剧集照旧豁免。详情页手动匹配弹层里那个「待刮削名称 / 年份」也改成同一套现算。

**刮削跑一轮就再也不动了。** 取批次时队列行按行删掉，扫描途中借的那 4 秒预算用完就 `break`，这一批没刮的条目行已经没了；而收尾那一次正式刮削和每一次借刮削都写成「队列行数 > 0 才开跑」，行数归零就被判成没活可干。于是刮到一半整台机器安静下来：不再发一个 TMDB 请求，左上角那句「待刮削 N」跟着掉回空，重开软件、再点「扫描刮削」都一样。现在三处开关前面先 `requeueUnscraped()` 补队列，预算用完退出前也补一次；「还剩多少」的口径改成「队列行 ∪ 未刮削且未锁定的实体」，与 mac 每轮现算未刮削清单同一件事。

**收尾那句按一次动作一本账。** 借刮削与收尾那轮各记各的账时，同一批条目会被数两遍，出现过「共处理 6 个条目：3 个没搜到，3 个年份对不上」这种一个更新都没有、海报墙却刚刷了五张的总结。现在一次用户动作只记一本账，收尾说「更新了 N 个条目；X 个没搜到，Y 个年份对不上，合并了 Z 个重复条目。」，一个都没更新时说的是「这一轮没有匹配到新的资料（…）」。

**验证。** 模拟器 + 假 WebDAV + 假 TMDB（故意摆两颗陷阱：`bicycle thieves` 同时返回 1948 原版（热度 20）与 2026 同名新作（热度 500），`流人` 只返回一部 2025 年的不相干华语片）。冷启动后服务端依次收到 `query='Bicycle Thieves'`（zh-CN / en-US）→ `ALT id=1001`、`query='Toy Story'` → `query='ToyStory'`、`query='流人'` → `query='Slow Horses'` → `SEASON id=8001 n=1` → `ALT id=8001`；陷阱那部 `ALT id=7001` 一次没出现。首页 `所有影视` 从 12 部收到 11 部，收尾写「合并了 1 个重复条目」，两张 Slow Horses 并成一张。重开软件的第一张截图上，已刮削的三张海报已经在屏，左上角同时写「刮削元数据和海报 (5/7)：Big Buck Bunny」。另有一份 JVM 用例（`build/harness/NameYearCheck.java`，拿真源码编译）覆盖用户给的两条路径、十组年份用例、`A.K.A.` 拆分与 Jellyfin / Emby 端点路径，全部通过。

细节与验证记录见 [2026-10-13-android-tv-mac-scrape-ladder-dedup-cold-posters.md](2026-10-13-android-tv-mac-scrape-ladder-dedup-cold-posters.md)。

## 移除就停、豆瓣兜底、片名年份再收一轮（1.31）

**移除媒体源要当场收手。** `removeSource()` 以前只删源和该源的文件行，扫描线程并不知道：剩下的源照扫、`ScanCollector.register` 照登记、刮削照开跑，左上角那句「正在扫描」就一直挂着。现在 `LocalEngine` 立一块 `abortRequested` 牌子，移除时先立牌再删源，四个位置看它：源循环开头（直接收工）、每个文件登记处（抛 `ScanAborted`，遍历当场停，一个文件都不再登记）、刮削批次循环（没刮的留在队列里，下一轮补回）、扫描途中借刮削的入口。收尾那句也跟着改口——已经立牌就只报「已停止扫描刮削。」，不再报一句「刮削完成：……」盖在用户刚做的动作上。

**豆瓣这一路补齐了。** mac 版有 `DoubanService` / `DoubanBindModalView`，TV 版此前完全没有。语义照它保持一致：豆瓣只做手动绑定，不参与自动匹配。新 `DoubanClient` 认桌面 / 移动版条目链接与裸编号，抓取之间至少隔 12 秒带抖动，遇到 403 / 429 / 验证页就把后续抓取按住 12 小时（截止时间落偏好，界面上说得出「什么时候再试」）；解析先 JSON-LD、再退回页面正则（`v:itemreviewed` 取片名、标题里的 `(19xx)` 与 `<span class="year">` 取年份、`又名` 取别名、`<span class="pl">导演 / 主演 / 类型 / 制片国家</span>` 取资料块），标题尾巴上的年份一律削掉；海报可用性照 mac，`qnmob`、`/q/60/`、`/w/300/` 这些缩略图不当海报用。库里新增 `doubanMetadata` 表（数据库版本升到 4，旧库 `onUpgrade` 建表）。入口是手动匹配弹层里多出来的那一行（说明文字 + 输入框 + 已绑定时的「解除豆瓣绑定」，按钮行变成「关闭 / 手机输入 / 绑定豆瓣 / 搜索」，手机推送的字段表里同时多了 `douban`）。展示两处：详情页元信息行 `年份 · TMDB ★ 8.1 · 豆瓣 ★ 9.1 · 类型 / 地区`，首页卡片评分角标同样两颗并排；TMDB 搜不到的条目（`tmdbId` 为空）绑定后由豆瓣写片名、年份、简介并置 `scraped = 1, isLocked = 1`，这就是「TMDB 匹配不到时豆瓣兜底」。

**选中海报别再加暗、年份输入框光标要在末尾。** `stylePosterFocus` 在放大之外还额外盖了一层暗色遮罩，遥控器每走一格海报就暗一下，看着像图在闪，去掉遮罩只留轻微放大与阴影。`styleInputFocus` 拿到焦点时把光标挪到文本末尾：以前一进输入框光标就在最前面，想改年份得先一路按右键把光标挪出去，实际手感就是「删不掉」。

**全角标点与罗马数字先折一遍。** `劇場版「Fate／stay night [Heaven's Feel]」 Ⅲ.spring song 2020 ...` 提取成 `00000`、同系列 `Ⅱ.lost butterfly 2019` 只剩「劇場版」，成因是同一个：清洗按词元做，而全角 `／`、「」、罗马数字 `Ⅱ` 既不算字母也不算数字，整段词被当垃圾丢掉。新增 `normalizeNameText()`：清洗之前把全角标点折成空格、`Ⅰ..ⅿ` 折成 `I..X`、全角数字字母折成 ASCII，相对路径与父目录名一并折；通用中文词表补上繁体的「劇場版」，清洗规则按 mac 那份重写。现在 `Fate stay night Heaven's Feel III spring song` / 2020、`... II lost butterfly` / 2019，`空战群英` 与 `流人` 的中文片名也照常提得到。

**规则早就对了，首页为什么还是旧名字。** `Signal` 记成 2017、`Vinland Saga` 记成 2005、`Paprika` 刮成 `Paprika Western`、`Millennium Actress` 刮成 `The Making of Millennium Actress`——1.29 / 1.30 修的是「这一次刮的时候怎么算」，而已经刮到资料的行是 `scraped = 1`（手动关联过的还带 `isLocked = 1`），压根不会再进队列，老账就那么留在库里。新增 `redecideStaleResults()`：每轮扫描摘要之后跑一次，把实体与一个代表文件 join 出来、按当前规则现算片名与年份，年份对不上或库里片名没有汉字而提取结果对得上的，一律强制重新入队；跑完把 `scrape_rule_epoch` 写成 31，只在规则升级后跑这一次，不会每轮重刮整库。

**刮完还是英文。** TMDB 的 zh-CN 搜索结果对这类作品常常就是拉丁名，旧版把候选标题原样写库，`空战群英.Masters.of.the.Air.S01.2024...` 就一直挂着 `Masters of the Air`。现在照 mac 的 `preferredTitle(chineseFallback:)`：先取 `/movie/{id}`（zh-CN）里的标题，含汉字就用；没有汉字就退到文件名或父目录里的中文片名（`applyChineseTitleUnlessLocalized()`），手动关联走同一条路。文件名里一个汉字都没有的资源（`Solo Leveling`）保留 TMDB 标题。

**从详情页返回不该回顶部。** 进详情前记下滚动偏移与聚焦海报的实体 id。旧实现有两处不生效：新 `ScrollView` 在第一次布局前会吞掉 `scrollTo()`，落地后又有一次媒体库重读重建墙，位置被冲掉——现在这份记录等 `post()` 里的 `scrollTo()` 真跑过之后再清账；`restorePosterFocus()` 旧写法是「屏幕上只要有东西带着焦点就不补」，重建后系统把默认焦点丢给第一个可聚焦控件，每次都它挡回来——改成「焦点不在这张卡上就补过去」。

**验证。** JVM 用例全部通过：`NameYearCheck`（年份取法十组、`A.K.A.` 拆分、媒体服务器端点路径）、`DoubanParseCheck`（真页面快照验片名 / 年份 / 又名 / 评分 / 导演 / 主演 / 类型 / 国家 / 海报，链接与裸编号五种写法都解析出同一编号，缩略图不当海报）、`ParseProbe`（用户给的十一条文件名逐条打印提取结果）。模拟器 + 假 WebDAV + 假 TMDB 跑真链路：数据库 v3→v4 建表正常，海报墙照旧带海报渲染；手动匹配里输入 `1395091` 绑定成功后弹「已绑定豆瓣《Perfect Blue》，豆瓣 9.1」，详情页元信息行变成 `1997 · TMDB ★ 8.1 · 豆瓣 ★ 9.1 · 剧情 动画 悬疑 日本`，首页那张卡片角标同时是 `8.1` 和 `9.1`；扫描途中移除媒体源，首页立刻归零且不再出现「正在扫描」；选中第三张海报进详情再返回，墙停在原偏移、焦点回到原那张卡。

## 遥控器改字、播放模式进播放页、特别季排最后（1.32）

**`S00E01` 是特别篇，不该并进第一季。** 解析器以前把 `season == 0` 一律抬成 1，于是 `Slow.Horses.2022.S00E01...` 和 `S01E01` 成了同一集，详情页只剩两份文件挤在一张卡里。现在 `parseEpisode` 记住这份季集号是不是从文件名（或目录提示）里明写出来的（`explicitSeason`），明写的 `S00` 就保持第 0 季；第 0 季在详情页排在所有季最后面，标签写「特别篇」，卡片标题写「特别篇第 N 集」。因为扫描是增量的，老库里已存的行不会重算，数据库版本升到 5，`onUpgrade` 里跑一次 `reparseEpisodeColumns()` 按当前规则把 `videoFile` 的季集号重写一遍；`insertVideoFile` 也在 `INSERT OR IGNORE` 之后补一条按 id 的 UPDATE，防止旧行顶住新结果。

**剧集没有「版本」这一说。** mac 版的版本一节条件是 `videoFiles.count > 1`，且只对电影成立。TV 版以前给每集都冠一句「版本 N · 文件名」，同一集两份拷贝就被说成两个版本。现在 `renderMovieVersions()` 保持 `files.size() <= 1` 直接不画（一部电影孤零零一条时那一节什么也没说明），标题用「版本 / 文件（N）」；剧集走分集剧照那一节，多个文件就是这一集的几份拷贝，标题改成「文件（N）」，按钮上就是原始文件名，路径与时长另起两行小字。

**手动匹配的四个按钮挪到候选上面。** 弹层里候选列表是从 TMDB 回来的长列表，按钮排在最底下就得先把它滚穿才点得到「手机输入」。顺序改成：源文件与关键词 / 年份 / 豆瓣输入区 → `关闭 · 手机输入 · 绑定豆瓣 · 搜索` → 候选列表，按钮行与列表之间留 10dp。顺手把两处按着别扭的尺寸改了：手机输入弹层的「关闭」不再占满整行，固定 216dp 宽居中、高度加到按钮标准高 + 10dp；「解除豆瓣绑定」改成按文字收宽、同样加高，红字危险操作不再是整条横幅。

**遥控器要能在输入框里挪光标。** 左右方向键以前整个被 D-pad 焦点导航接管，光标钉在文本开头，想删掉年份前两位只能一路按右键按出焦点。`dispatchKeyEvent` 现在在 `handleDpadChain` 之前先问一次 `moveCaretInFocusedField()`：焦点是 `EditText` 且左右键按下时，有选区就先收拢到选区靠方向的一端，没选区就把光标挪一格；已经到文本头尾就返回 `false`，交回焦点导航，跨出输入框的手感不变。删除键（含遥控器的确认位删除）因此能精确落在光标处。

**点「手动匹配」有概率自己弹回详情页。** 真因不在弹层，在详情页：刮削与播放进度都会异步回来刷新详情，而 `renderDetail()` 开头就是 `closeAllOverlays(); root.removeAllViews();`，刷新恰好落在你刚打开弹层那一下，弹层就被自己人拆了。现在 `Overlays` 多了一个 `onStackChanged` 回调，`refreshDetail` 与 `refreshPlaybackSettingsForDetail` 见到 `overlays.hasOpen()` 只换数据不重建页面，把重绘记在 `pendingDetailRerender` 上，等弹层关掉那一刻再补一次；`renderDetail()` 自己接管时先把这个待办清掉，不会重绘两次。

**播放页左上角该说片名。** 以前那一行是文件名，蓝光和 `S00E01` 这类命名在电视上就是天书。现在标题走 `playerHeadingFor(file)`：刮到资料就用详情页片名，没有才退回文件标签；第二行走 `playerSummaryFor(file)`，把季集号（含「特别篇第 N 集」）、分集标题和分辨率音轨摘要用 ` · ` 连起来。进度条右侧补上剩余时间（`-M:SS`），时长未知时显示 `--:--`，无障碍描述里带上「已播 / 总时长」。

**播放模式挪进播放页。** 设置里那节「4K DV/HDR 播放模式」连分段控件和说明一起删掉，播放页工具条多了一个按钮，文案就是当前模式，点开两项菜单：`兼容字幕播放 · 字幕由播放器画` 与 `高性能直出 · 视频直接进解码器`。切换走 `switchPlaybackModeDuringPlayback()`：先写偏好，再 `postPlaybackProgress()` 把当前位置记进播放进度，然后原地重开同一个文件，接着看；焦点链上字幕按钮的右边就是这个按钮。ISO 一律不走直出（`shouldUseDirectPlayback()` 里先判 `isIsoFile`）。

**直出模式下为什么看不到内封字幕。** 直出用的是 `vo=mediacodec_embed`：解码后的帧由 MediaCodec 直接送进 Surface 上屏，mpv 的字幕与 OSD 渲染器压根没机会参与合成，所以内封的文本字幕和 PGS 位图字幕都不显示——不是字幕没读到，是画不上去。1.32 的做法是在字幕菜单里，当前是直出且这个文件确实有字幕轨时，末尾多一项「直出不渲染内封字幕 · 改用兼容字幕播放」，点一下当场切过去、接回原进度。想两头都占，还可以走三条路：Android 侧盖一层字幕 View（自己排版，能顺带做弹幕与字幕样式）、播放前把内封字幕抽成临时 SRT 再 `--sub-file` 挂上、或者选中字幕轨时自动降级到兼容模式（本版本按用户显式选择处理，没有偷偷降级）。

**蓝光 ISO 其实从来没播起来过。** 报的是 `播放失败：no audio or video data played（-16）`，看着像解码失败，实际是根本没有码流进来：随 APK 打包的 `libmpv.so` / `libavformat.so` 里没编 libbluray（`bd_open` 一类符号、`bd` / `dvd` 协议名都搜不到），`bd://` 这个地址以前就没人能打开。现在走已有的本机代理：`RemoteIsoStreamServer.prepare()` 用 HTTP Range 读 ISO 的 UDF / ISO9660 目录树，在 `BDMV/STREAM` 里挑最大的那条 m2ts 主视频，用 `http://127.0.0.1:<port>/remoteiso/<route>/stream.ts` 喂给 mpv，走的就是普通 TS，兼容模式下字幕、进度、seek 都正常。DVD 的 `VIDEO_TS` 还不认，报错文案会明说「目前只支持蓝光 ISO」。这一条是结构性修复，真机验证需要 NAS 上一份真蓝光 ISO。

**选中态去掉蓝框。** `Theme` 里新增 `focusFill(base)`，所有 focused drawable 的 accent 描边换成「主体色往焦点色提一点亮」，深色主题提 20%、浅色提 10%，边框粗细归零，只留 1.045 倍轻微放大与阴影。改动覆盖按钮、图标、行、输入框、海报卡片、角标和播放器三处控件：遥控器走到哪，哪只是亮一点、大一点，不再被描一圈蓝。

**验证。** JVM 用例（`NameYearCheck`、`DoubanParseCheck`）全绿。模拟器 + 假 WebDAV（夹具补了一条 `S00E01` 特别篇和同集第二份拷贝）跑真链路：详情页季标签是 `第 1 季 | 第 2 季 | 特别篇`，特别篇卡片标题「特别篇第 1 集」；那一集下面是「文件（2）」加两条原始文件名，没有「版本」字样；手动匹配弹层顺序为输入区 → 按钮行（y 677-752）→ 候选列表；年份输入框里光标左移两格再按删除，`2022` 变 `222`；播放页左上角是 `中文译名8001` + `第 1 季第 1 集`，工具条上的模式按钮点开两项菜单，切到直出后原地重开；设置弹窗里已经没有播放模式那一节，滚到底只剩 `刮削与播放偏好` / `基础设置` / `关于与更新`。没能在模拟器上验的两处：夹具文件时长为 0，进度条右侧只能显示 `--:--`；假 WebDAV 回的是占位字节，起播就 `loading failed (-13)`，所以内封字幕与 ISO 都留给真机。

## 兼容模式播 4K 不再那么吃力（1.33）

**卡顿的大头在哪。** 兼容字幕播放是 `vo=gpu` + `hwdec=mediacodec-copy`：解码交给硬件，但每帧要从解码器拷回内存、上传成纹理，在 GPU 上跑色彩管理与 HDR→SDR 色调映射，最后再把字幕与 OSD 合成一次。4K 10-bit 一帧 12MB 出头，几十 fps 的上传带宽先吃掉一块预算。以前还叠了 `hdr-compute-peak=yes`，让 mpv 自己逐帧降采样回读算峰值亮度（文档原话是「可能对性能有较大影响」），而绝大多数 HDR 文件本来就带 MaxCLL / mastering display 元数据可以直接用。电视上还有第三层：兼容模式画在 `TextureView` 上，每帧要在应用的 HWUI 场景里再多走一次全屏带纹理绘制与一次同步等待。

**这一版做的三件事，都在兼容分支。**

1. `hdr-compute-peak` 由 `yes` 改 `auto`：文件带峰值元数据时直接用元数据，不再逐帧回读。
2. `fbo-format=rgb10_a2`、`dither-depth=8`、`blend-subtitles=no`、`sub-gauss=0`：FBO 从高位宽浮点退到 10-bit 整型，抖动按 8bit 算，字幕层不再混进视频帧多 blend 一次。
3. 新增 `useSurfaceViewPlayback()`：命中直出、`isLikely4K` 或 `needsManagedColorPlayback` 的文件，兼容模式也画在 SurfaceView 上（与直出同一条载体），少一层 HWUI 合成；1080p 的日常播放维持 TextureView，不跟着换渲染路径。`MpvVideoView` 因此多了第三个参数，`replacePlayerViewForPlaybackMode()` 也跟着接文件参数。

**为什么没顺手做「直出 + 自己画字幕」。** 覆盖层其实早就在：`SubtitleCue` 文本层 + `PgsSubtitleView` 位图层，由播放进度驱动。问题是它只被服务端字幕接口喂过（`api.subtitleUrl(track, ticket)`），独立版没有那条接口，内封字幕就直接交给 mpv，而直出的 `vo=mediacodec_embed` 不参与 OSD 合成，什么都画不上。要补的是「本机把内封字幕抽出来」这一步，两条路：用随 APK 打包的 libavformat 加一小段 JNI，把选中字幕轨 demux 成文本 cue（SRT / ASS / VTT）或 PGS 包流喂给现成覆盖层（容器 MKV / MP4 / TS 通吃，蓝光原生的 PGS 也能显示）；或者叠一个只渲染字幕的第二个 mpv 实例当透明层（libass 全套样式与 PGS 白拿，代价是同一份文件多一路 demux 与两实例的时钟纠偏）。

**验证。** 模拟器 + 假 WebDAV：`2160p ... HDR` 那条走新的兼容 + SurfaceView 载体，日志到 `end-file reason=error error=loading failed (-13)`（假服务回的是占位字节），说明 SurfaceView 的 `surfaceCreated` 正常触发、播放器照常挂载；新加的四个选项没有触发任何选项错误，`mpv_initialize` 通过。真实帧率收益要在真机上对着 4K 原盘看，模拟器（SwiftShader）测不出带宽。

## 内封字幕转成 sidecar 写回媒体源（1.34）

**要解决的问题。** 直出模式（`vo=mediacodec_embed`）看不见内封字幕，兼容模式播 4K 又要吃色调映射；而覆盖层其实早就在——`SubtitleCue` 文本层 + `PgsSubtitleView` 位图层，由播放进度驱动，只是独立版从没喂过它。缺的就是「本机把内封字幕抽出来」这一步。抽出来之后两个模式都能显示，还能顺手拿到一个能给别的播放器用的外挂字幕。

**为什么必须整轨扫一遍。** Matroska 把字幕块和音视频块交错写在同一条字节流里，`Cues` 索引只定位到簇、不定位到某条轨的某个块。想覆盖到第 80 分钟，就得把那段字节翻过去。所以「只读一小段拿全部字幕」在 MKV 上不存在，实时窗口式抽取也意味着播放时正在放的那段要边播边下载重读。既然成本是一次顺序读，就把它整个挪到后台：转好的产物贴着视频放，播放只读几十 KB 的文本文件。PGS 位图轨一条字幕就是一帧 100~500KB 的位图，整片能有几百 MB，就更不适合播放时现抽。

**抽取器。** `subtitle/MatroskaSubtitleExtractor`：自己写的 EBML 遍历（元素 ID 要连长度标记位一起比对，数据 vint 才剥标记位）、`Cluster → SimpleBlock / BlockGroup` 顺序走、每簇一次分块区间读、读过的字节不回读。时间码按容器 `TimecodeScale` 换算，交织（laced）块跳过并计数（字幕轨极少用 lacing，宁可少一条也别画错时间）。读文件走 `SeekableSource` 抽象：本地 `RandomAccessFile`、WebDAV 一次 Range 请求、SMB 一个 `SmbRandomAccessFile` 句柄从头用到尾。输出三种：`S_TEXT/UTF8` / `S_TEXT/WEBVTT` 写成 SRT；`S_TEXT/ASS` 保留 ASS 并带上容器里的脚本头，样式不丢（Matroska 的 ASS 块不带 `Dialogue:` 前缀，抽取时补上并按块时间重算时间轴）；`S_HDMV/PGS` / `S_DVBSUB` 原样拼成 `.sup` 段流。

**写回。** `local/SubtitleSidecarService` 按 `Access` 接口对接三种媒体源：文本轨每个窗口整份重写（几十 KB 而已，重写比打补丁简单也不容易写坏），续跑时先把盘上那份解析回来当种子，不会把上次转好的前半段冲掉；PGS 轨先追加到本机临时文件，跑完一次性流式 `PUT`（`Http.putFile`，几百 MB 不进内存），本地源也改成流式拷贝。只读共享会回 403 / 409，提示「媒体源不接受写入（HTTP nnn），共享可能是只读的」。

**怎么跑。** 1.37 起电视端不再自动抢批量：扫描收尾只跑 `sidecarRecogniseSweep(12)` 认一遍媒体源里现成的外挂字幕，抽取留给 NAS 那台服务；要电视自己抽，播放页字幕菜单点「后台转档这条的内封字幕」只转当前这一条。转好的条目在同一个菜单里列成「已存媒体源 · 中文（SRT · 612 条）」，选中就把 mpv 那条内封轨关掉（`sub-lang=no`）再读 sidecar 进覆盖层，免得兼容模式画两遍。进度只写在首页左上角那行日志里（弹层里不再重复一遍）。

**顺带修的两个 bug。** `PgsSubtitleParser` 把段头读成 13 字节、同步字当 `'PG'`：规范是 `'PJ'`（`0x50 0x4A`）加 10 字节头，PTS 按 MPEG 时间戳布局（`'1000' + pts_ext(3) + '1' | pts[32..18] + '1' | pts[17..3] + '1'`）解，丢掉低 3 位换 1/8 帧精度；以前独立版没有本地 PGS 来源，这条路没被走过所以没暴露。另一个是新抽取器自己的：EBML 元素 ID 比较前把长度标记位剥了，`0x18538067` 变成 `0x08538067`，所有 ID 都对不上、整份结构读空——夹具当场抓到。

**这一版的边界。** 只处理 MKV / WEBM：TS / M2TS / 蓝光 ISO 里的 PGS 走的是 MPEG-TS 描述符 + PES，MP4 内封字幕走 `tx3g` / `wvtt`，都不在这套 EBML 读取器里，会写一条「没有能转的字幕轨」的账（状态 `unsupported`，不会再反复重试）。每条视频只转最该看的那一条轨（用户设的字幕语言优先，其次容器标了默认轨的，再不行取第一条），多条语言并列、跟着视频改名、转档进度单独 UI 都还没做。`.sup` 的调色板段 / 对象段字段偏移沿用了覆盖层解析器现有的读法，还没拿真原盘对过，位图字幕在电视上的显示效果留作下一步核对。

**验证。** 新增 JVM 用例 `build/harness/SidecarCheck.java`（35 项全绿，含 ASS 文本字幕的时间轴与控制序列处理，跑法 `zsh build/tvtools/harness.sh`，WebDAV 那半截要允许本机绑端口）：夹具由 `build/patches/mkmkv.py` 现造（视频轨 + `S_TEXT/UTF8`(chi) / `S_TEXT/ASS`(eng) / `S_HDMV/PGS`(zho) 三条字幕轨 + 三个簇 + 一条 laced 块 + 一个非 MKV 文件），覆盖探轨与语言归一（`chi` / `zho` → `zh`）、SRT 三条时间轴（`00:00:01,000 --> 00:00:05,000` 等）、ASS 补 `Dialogue:` 前缀并保脚本头、`.sup` 能被覆盖层解析器读回两张画面且按 PTS 定时、laced 块不入字幕、中途收工再从字节偏移续跑时前两句不被冲掉、非 MKV 直接不转；后半截用 JDK 自带的 `HttpServer` 假 WebDAV，验 Range 探轨、`PUT` 写文本产物、流式 `PUT` 写 `.sup`、`HEAD` 认已存在。真机侧：覆盖安装走 v5→v6 迁移，启动直接进海报墙，整轮扫描刮削无 `no such table` / `SQLiteException`，（当年验过的设置里「内封字幕转档」三段开关，1.37 起这条已经去掉。）字幕菜单里选 sidecar 与 PGS 上屏仍待真机（夹具文件起播就 `loading failed (-13)`，进不去播放页）。

## 模拟器与真机验证（1.12）

> 2026-10-26：下面这套本机安卓虚拟机已经从项目里删掉了——`.avd`（两台 AVD，4.8G）、`.android-sdk/system-images`（android-34 android-tv arm64-v8a，8.1G）、`.android-sdk/emulator`（1.2G），合计约 14G。日常验证改用 Mac Android Subsystem（`/Applications/Mac Android Subsystem.app`）：它自带 qemu 与 `bridge.apk`，APK 装完在 `~/Applications/Android Apps/` 里生成 `OmniPlay.app` 这类启动项，不需要 AVD。项目里的 `.android-sdk` 只留打包要用的 `build-tools` / `platforms` / `platform-tools` / `cmdline-tools` / `ndk` / `cmake`（3.2G），`release.sh` 与 `harness.sh` 都不碰被删的三样，删完照常出包、JVM 用例全绿。要恢复模拟器，下面的命令原样跑一遍即可（`sdkmanager` 会重新拉那 8.1G 镜像）。
>

```sh

"$SDK/cmdline-tools/latest/bin/sdkmanager" --sdk_root="$SDK" \
```

1.12 是在模拟器上跑出来的第一轮，修的都是「没设备就看不见」的问题：

| 症状 | 成因 |
| --- | --- |
| 本地目录扫完报 `Syntax error in regexp pattern`，整库扫挂 | `LocalMediaNameParser` 里 `(?!…)\b` 给断言加了量词，Android 的正则是 ICU 实现，不接受；OpenJDK 能编译，所以 JVM 用例查不出来 |
| `待刮削 N 个条目` 每扫一次翻一倍 | `enqueueScrape` 是裸 INSERT，同一实体重复入队，TMDB 也重复查 |
| 设置 / 媒体源弹层刚打开时没有焦点框 | ScrollView 被当成控件收进了焦点网格，系统兜底把焦点给了它，而容器不画焦点圈 |
| 本机影片点播放报 `播放失败：loading failed (-13)` | 交给 mpv 的是相对路径，mpv 拿它去 `/` 下面找文件 |
| 反代和 Key 都填对了，检测却说「TMDB 无法访问」 | 1.16 前有三处：检测发的是相对地址、反代没补 `/3`、走反代时凭证不发。都已修，现在检测会说是 401 还是 404 还是连不上 |

配套加了 `/tmp/pitest/run-regex.sh`（`REGEX_OK`），静态查「量词紧跟在断言后面」这类只有 Android 会炸的写法。

JVM 侧一共八个用例：`run-webdav.sh`（`WEBDAV_OK`）、`run-smb.sh`（`SMB_OK`）、`run-saved.sh`、`run-phone.sh`、`run-regex.sh`（`REGEX_OK`）、`run-bluray.sh`（`BLURAY_OK`）、`run-tmdb.sh`（`TMDB_OK`）与 `/tmp/lanprobe/run.sh`（`ALL_OK`）。它们都只编 `local/` + `data/`，所以 `local/` 不能反向依赖 `ui/`。

### 常见问题

- `JAVA_HOME` 不满足 JDK 17–23 时 AGP 会直接报 JDK 版本错误；`/usr/libexec/java_home -V` 可列出本机可用 JDK。
- 首次构建卡在 Gradle 发行版或依赖下载，属于网络问题，确认可访问 `services.gradle.org`、`dl.google.com` 与 `repo1.maven.org` 后重试。
- 修改 `versionCode` 后记得同步 `app/build.gradle`；TV 端“软件更新”入口按 versionCode 判断是否有新版本。
- 构建别再带 `--offline`：`com.google.zxing:core` 不在本机 Gradle 缓存里时，离线模式会在 `checkReleaseAarMetadata` 直接失败，联网跑一次补上缓存即可。
- 若 Gradle 报 `FileLockContentionHandler ... Operation not permitted`，通常是沙箱/防火墙限制了本地回环端口，换普通 shell 或在允许网络的环境下重试。
- 手机打不开“手机输入”页面：先确认手机与电视连的是同一个 SSID / 同一网段；路由器开了 AP 隔离（客户隔离）时客户端互相不可见，需要在路由器上关闭；电视处于多网卡或访客网络时，`pageUrl()` 取到的可能不是手机所在网段的地址，可按页面提示改用手输地址。
- 用 JDK 24+ 构建时 Gradle 8.14 会在 Groovy 脚本编译阶段报 `Unsupported class file major version 70`（JDK 26），或在 `core-for-system-modules.jar` 的 `JdkImageTransform` / `jlink` 步骤失败；换 JDK 17–23 即可，本机可用独立解压的 Temurin 17 目录，macOS 上 `JAVA_HOME` 要指到 `.../Contents/Home`。
- 从 versionCode 18 及更早版本升级时，SQLite 会跑 v1→v2 迁移：给 `movie`/`tvShow` 补 `tmdb_id`/`genres`/`directors`/`casts`，给 `videoFile` 补 `episode_subtitle`，新建 `tvEpisode` 与 `offlineCache` 表；迁移只加列建表，不动已有数据。
- 局域网扫不到 WebDAV：判定规则是 OPTIONS 返回 `DAV` 头、或 PROPFIND 返回 207、或专用端口（5005 / 5006 / 8443 / 8010 / 8011 / 8000 / 5244 等）上吃到 401 / 403（OPTIONS 与 PROPFIND 任一即可）；80 / 443 / 8080 这类共享端口只认 `DAV` 头或真 207，避免把带登录的普通 Web 管理页当成 WebDAV。服务挂在其它端口时（例如 CloudDrive 的 19798），按页面提示手动填写完整地址后登录即可；扫描总时长上限 45 秒，NAS 唤醒或响应慢时可能来不及，重扫一次通常就有。
- WebDAV 登录报 `Expected one of [OPTIONS, GET, HEAD, POST, PUT, DELETE, TRACE, PATCH]`：那是 Android `HttpURLConnection.setRequestMethod` 抛的 `ProtocolException`，说明该设备不支持非标准方法；1.10 起 WebDAV 走自带的 `Http` 客户端，不应再出现，如果仍然出现请确认安装的是 v1.10 或更新（设置页第一行有版本号，也可看 APK 文件名）。
- 点 SMB 后 App 直接退出：v1.10 起不会再静默退出，登录框或登录页会给出原因（例如 `NoClassDefFoundError：jcifs.xxx` 或 `SmbAuthException：Login failure`）。若显示的是「上次异常退出：…」，那行文字就是崩溃原因，按它排查即可。
- WebDAV 目录名显示成 `%E4%B8%AD%E6%96%87…`：1.16 起列表、登录框、已保存连接都会把路径部分解回中文名。若仍是编码串，说明那串不是百分号编码（服务器返回的就是字面量），把地址原文发回来即可判断。
- 移除媒体源后首页还剩一堆卡片：1.17 起 `removeSource` 会连带清该源的文件、实体、剧集、刮削队列与缓存记录；1.20 补上「移除发生在扫描进行中」这一种——那一轮扫描还会把文件登记回来，现在 `registerFile()` 会先看源在不在，扫描收尾再按活着的源清一遍（`purgeUnknownSources`）。若装机版本更旧，用媒体源面板的「清空媒体库索引」也能清干净。
- 同一台服务器换过密码后连不上：登录框会回填保存过的账号密码，改完密码点“登录”即会覆盖旧记录，已挂载目录保留。

### 遥控器操作上遇到的问题先看这里

- 焦点跑到看不见的位置 / 方向键像没反应：1.11 起每个弹层都会把焦点收进自己内部（`rescueFocusIntoTopPanel`），再出现这种情况请记录「在哪个界面、按了哪个键、焦点从哪到哪」，网格声明缺控件是唯一的成因。
- 方向键往下滑却回弹：1.14 起面板行序由 `FocusGrid.rowsFrom()` 按布局推导、滚动跟随用布局位移归一化，两者都不再依赖手工行序；如果还能复现，请记录「在哪个面板、焦点在哪个控件、按了几次 DOWN」，那说明该面板有控件没被 `rowsFrom` 收到（只有 `isFocusable=false` 或 `View.GONE` 的控件会被跳过）。
- 原盘 / 蓝光目录扫出来一堆条目，或者反过来一个条目都没有：先看媒体源面板的扫描报告里有没有「蓝光非正片分卷跳过 N」。没有这一句说明 walker 没走进 `BDMV/STREAM`（多半是路径里又出现了被当成垃圾剪掉的目录名）；有这一句但数字不对，就是体积没读到（服务器不给 `getcontentlength`、SMB 拒绝 `entry.length()`），此时按分卷号最小的那条兜底。
- 弹层往下走再往上走滑不回顶部：1.17 起滚动跟随只按布局坐标计算中线落点，首行归零、末行到底。若还能复现，请记录「在哪个面板、焦点在哪个控件、按了几次 UP」，那说明该面板有控件没被 `rowsFrom()` 收到。
- WebDAV 源挂载成功、TMDB 也验通了，首页却一直是「待刮削 N 个条目」且数字在两个值之间来回跳：1.18 起修好。此前挂载路径带中文时相对路径会被算成编码过的文件名，查询词是垃圾；队列又按行入队、整表清空，计数与出队口径不一致。先升级到 v1.18，再点一次「扫描刮削」，旧条目会当缺失文件清掉后重新登记。
- 左上角一直挂着「待刮削 255 个条目」，且一部分卡片名字还是整串文件名：1.19 起修好。文件行绑着的实体被当空壳裁掉，队列行了跟着变孤儿，名字就停在第一次入库那轮。升级到 v1.19 后点一次「扫描刮削」即可自愈，不必清库。
- 从桌面点开应用先看到一屏错误日志：1.19 起冷启动不再做会话检查，崩溃摘要只是右上角一条 Toast。
- 打开软件先进一屏媒体源页，或者一直停在「正在扫描媒体源」：1.21 起修好。前者是空库被当成「还没配好」，后者是挂载时那层全屏 loading。升级到 v1.21 后首屏一定是海报墙，空库时墙上自带「添加媒体源」，扫描刮削全在后台跑。
- 点「扫描刮削」像没反应：1.21 起要么按钮变「扫描中」、横幅重新出现，要么弹一句「扫描刮削正在进行中」。若两者都没有，说明那一轮扫描已经卡在 `scanRunning` 上，把当时左上角横幅的文字发回来。
- 刮削跑完一次就再也不刮了、某几张海报永远是占位字母：1.24 起修好。旧版队列行在取批次时删掉，请求失败一次就等于这条目被踢出队列，而扫描只给新登记的文件入队。v1.24 起每轮刮削前会把「还没刮到资料又没锁定」的实体重新排回队列（与 mac 版每轮现算未刮削清单同一条规则），失败的条目下一轮自动再试。
- 左上角看不到扫描刮削进度：1.24 起只要还在扫描、还在刮削、或者队列里还有条目，那一行就一直在，并把「为什么没刮到」写清楚（TMDB 无法访问 / 没搜到 / 年份对不上 / 请求失败）。
- 左上角写着「正在扫描中」但一张新海报都不出现：1.23 起修好。旧版只在文件名解析出中西文片名时才把条目送进刮削队列，解析不出的文件永远排在队列外，看着就是「扫完了但没刮」。v1.23 起解析不出就用展示标题兜底入队，收尾文案也会分开报「N 个请求失败 / N 个没搜到 / N 个年份对不上」，一眼能看出是没跑还是没搜到。
- 详情页写着已刮削、首页卡片却还是占位字母和旧片名：1.22 起修好。首页用的是内存里那份媒体库名单，刮削跑完后没人回头重读它；从详情页、播放器返回首页时现在都会重读一次并就地补卡片。装机版本更旧的话，手动点一次「扫描刮削」也能刷出来（那一轮结束会整墙重建）。
- 点海报就闪退，日志写 `No static method encode(Ljava/lang/String;Ljava/nio/charset/Charset;)… in class java.net.URLEncoder`：1.21 起修好。`URLEncoder.encode(String, Charset)` 要 Android 13（API 33）才有，`minSdk` 26 装机跑的是 `WebDavClient.streamUrl()` 那条老路；v1.21 换成字符串重载。同类坑（`readAllBytes`、`transferTo`、`Path.of`、`URLDecoder.decode(..., Charset)`）全库已扫过一遍。
- 未刮削的卡片名字是一整串 `The.Movie.2024.1080p.BluRay.x265-GRP`：1.18 起按 mac 版规则先按发布元信息截断再入库；已经入库的旧条目名字不变，用「清空媒体库索引」后重扫即可换成短名。
- 遥控器走动时画面明显掉帧：先说清「在哪个界面、往哪个方向、连续按还是单按」，并附上海报数量（首页计数文案里有）。1.17 把每次焦点变化新建背景改成换引用，1.19 又砍掉逐条扫描进度、整墙重建与重复刮削三处（模拟器实测没有 20ms 以上的帧）；剩下的地板主要来自不复用的海报网格，`RecyclerView` 化是下一步。
- BACK 关掉弹层后原按钮点不动：每个 `Overlay` 都带 `onClose` 回调清宿主字段，若再出现请确认那个弹层是否漏了 `onClose`，或宿主字段被别处提前赋值过。
- 设置页改完一个开关后焦点跑掉：应停在被改的那一项上（按标签找回），若仍跳回顶部说明该行文字随状态变了，报上来补匹配规则。
- 弹层套弹层（登录框里点“手机输入”，或设置里点“用手机输入 TMDB 配置”）关闭后应回到打开它的那个按钮；回到顶部或回到屏幕外都是回归。
- 刚打开某个界面却看不到焦点框：那是焦点落到了 ScrollView 上。布局用的滚动容器一律 `setFocusable(false)`，控件一律由 `FocusGrid.grab` 上焦（首次 `requestFocus()` 会被还没布局的视图拒掉，`grab` 会在布局后补一次）。

- 换主题后如果标题、工具栏或海报占位还是旧配色：换肤必须走 `applyThemeChange()` 整屏重建，只重画列表不算换肤。
- 详情页出现 `NullPointerException（putVal:…）` 之类的浮动提示：那是被捕获的主线程回调异常，`CrashLog.summarize()` 已带上抛出位置，完整栈在 `/data/data/com.omniplay.tv/files/omniplay-tv-crash.txt`。
- 左上角写着「正在扫描媒体源...」几分钟不动、也不见新文件上墙：1.25 起修好。扫描阶段的进度以前不落库，界面只能显示开头那句；现在会写「扫描中 (1/3)：源名 · 已发现 N 个文件」，每个源扫完再报「完成：源名（新增 N）」。
- 移除媒体源后首页还剩一张未刮削卡片，或者左上角一直挂着「正在扫描媒体源」：1.25 起修好。扫描正中间移除的源当轮就被打断（「已移除：源名，本轮跳过」），收尾按还活着的源清理，首页也只认最后一次读取结果。旧版请点一次「扫描刮削」，那一轮收尾会把孤儿条目清掉。
- 打开软件停在中间一行「正在加载媒体库」不动：1.25 起修好（并发读取互相覆盖，空库时没人负责渲染首页）。v1.24 及更早上遇到就点一次右上角「扫描刮削」。
