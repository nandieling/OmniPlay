# 2026-10-30 · 1.45：内封字幕、直出规则、播放页菜单

对应版本：`versionCode 56` / `versionName 1.45`。接续当天的 1.44（NAS sidecar 发现 + 手机端对齐电视端）。

## 一、内封字幕为什么在兼容模式里看不见

现象：1080p 的 MKV 用兼容字幕播放，字幕菜单里只有「关闭字幕 / 再找一遍媒体源里的外挂字幕 / 后台转档这条的内封字幕」三条，一条内封轨都不列；切到高性能直出，按 1.44 定的规则内封轨该收起来，结果连「已收起 N 条」那行的 N 都是 0。

根子在数据源，不在菜单。独立版入库走的是 `Models.VideoFile.local(…)`，那一串构造参数里 `audioTracks` 与 `subtitleStreams` 直接写的 `Collections.emptyList()`，从此再没人填过：

```java
return new VideoFile(id, relativePath, fileName, mediaKind, 0,
        positionSeconds, isWatched,
        seasonNumber, episodeNumber, episodeTitle,
        "", "", 0, 0, "", "",
        Collections.emptyList(), Collections.emptyList(),   // ← 音轨、字幕轨永远是空的
        null, playbackUrl);
```

电视端之所以看得见，是因为它压根不依赖这份清单：`MainActivity.showSubtitleMenu()` 一进来先 `refreshRuntimeTracks()`，问 mpv 要 `track-list`，有实时轨道就用实时轨道。手机端 1.44 那版把菜单抄齐了，却把这条数据来源抄漏了。

## 二、改法：先问 mpv，问不到再自己读容器

手机端 `PhoneMainActivity` 补上与电视端同一套 track-list 读法：

```java
private void refreshRuntimeTracks() {
    int count = (int) Math.round(playerView.getDoubleProperty("track-list/count", 0));
    if (count <= 0) {
        return;                       // 播放器还没报数，保留上一次的结果
    }
    for (int index = 0; index < Math.min(count, 128); index++) {
        String prefix = "track-list/" + index + "/";
        String type = runtimePropertyString(prefix + "type");
        if ("audio".equals(type)) audio.add(readRuntimeTrack(prefix, audioOrdinal++, "audio"));
        else if ("sub".equals(type) || "subtitle".equals(type)) subtitles.add(…);
    }
}
```

每条读 `id` / `codec` / `lang` / `title` / `demux-channel-count` / `selected` / `default`，`selectedRuntimeSubtitleId`、`selectedRuntimeAudioId` 记选中态，菜单里的 ✓ 就认这两个键——这正是之前「看不出选中了哪条轨道」的正解。

mpv 一条轨道都没报（文件还没装载完，或某些容器它就是不报）时，退一层：直接读容器。`LocalEngine` 新增三个方法。

- `embeddedSubtitleTracks(videoFileId, relativePath)`：只解析 EBML 头拿轨清单，不碰数据块，一部片只探一次（`containerProbeKey` 记着，别把 WebDAV 的 HEAD 打爆）。
- `readEmbeddedSubtitle(videoFileId, relativePath, trackNumber)`：整轨抽出来，文本轨回 SRT / ASS 原文，位图轨回 `.sup` 字节流。
- `transcodeSidecar(videoFileId, relativePath, trackNumber)`：原来只有「挑一条最该转的」，现在能按用户点名的轨号转。

`MAX_INLINE_PGS_BYTES = 24 MB` 是在抽取回调里边抽边累加判的，超了当场抛，交给可续跑的后台转档，而不是把几百 MB 的 PGS 塞进电视内存。

选轨的分工因此很清楚：

```java
if (useRuntimeSubtitles) {              // mpv 报了轨：交给 mpv 自己渲染
    playerView.setSubtitleTrack(track.mpvId);
} else if (!containerTracks.isEmpty()) { // 只有容器看得见：文本轨走覆盖层，位图轨走转档
    selectContainerSubtitle(file, trackNumber, format);
}
```

顺带把两个小的说法问题改掉：容器归一化出来的是 `zh` / `en` 两位码，而 `trackLanguageName()` 只认 `chi` / `zho` / `eng`，菜单里会露出「内封 3 · zh · SRT」这种裸码（两位三位现在都认）；音轨在播放器还没报轨道时，原先只甩「暂无可切换音轨」，现在写「播放器还没报音轨，稍等一下再打开」。

## 三、直出档的字幕菜单规则

电视端 1.44 已经做了（内封收起、换成一行「直出不渲染内封字幕（已收起 N 条）· 改用兼容字幕播放」，点它切回兼容），这版把同一条规则在手机端落实，并且修好了它的计数：`embeddedCount` 现在按 `runtimeSubtitleTracks` → 容器清单 → `file.subtitleStreams` 的顺序取，之前永远是个位数 0。

## 四、播放模式与画面比例改成菜单

手机端「模式」「比例」原先是盲切（点一下换一档），看不见当前用的是哪档。现在点开是两行带 ✓ 的选择，与电视端 `showPlaybackModeMenu()` / `showAspectModeMenu()` 一致；`togglePlaybackMode()` 一并撤掉，不留一条没人调的分支。

## 五、屏幕常亮判反了

```java
public boolean isPlaying() {
    if (!initialized || paused) return false;
    if (readFlag("pause", false)) return false;
    return !readFlag("eof-reached", false);
}
```

原来是 `"yes".equals(getStringProperty("idle", "no"))`。mpv 的 `idle` 意思是「没装载文件」，正播着的时候它是 `no`——等于暂停和放完才认定在播，看电视的时候反倒把 `FLAG_KEEP_SCREEN_ON` 摘了。电视端与手机端共用这个方法（两处 `syncKeepScreenOn()`），一起好。`readFlag` 对 `yes` / `true` / `1` 都认，读不到时按「在播」走，宁可多亮一会儿。

  - 直出档字幕弹窗：内封那行没了，换成 `直出不渲染内封字幕（已收起 1 条）· 改用兼容字幕播放`（`/tmp/m-sub-direct.png`）。
  - 媒体源里现成的外挂字幕照旧自动挂上并打勾：`✓ 媒体源外挂字幕 · 中文（SRT）`（`/tmp/m-inter-sub-compat.png`）。
  - 播放模式菜单 `✓ 高性能直出 · 视频直接进解码器`、画面比例菜单 `✓ 保持比例 · 上下留黑边`。

## 七、MAS 操作备忘（省得下次再踩）

- 应用会跑到第二块屏（`dumpsys activity activities` 里 `Display #2`）：`uiautomator dump` 与 `screencap` 抓的都是 `Display #0` 的 LineageOS 桌面，看着像「App 自己退到后台」。启动一律带 `--display 0`：`am start --display 0 -n com.omniplay.tv/.LauncherActivity`。
- 扫描进行中 `uiautomator dump` 会等窗口 idle，一次能卡十几秒，脚本里所有等待都要按这个量级设。
- 控制条四秒自动收起，点菜单按钮前先点一下画面（`input tap 540 300`）把 chrome 叫回来。
