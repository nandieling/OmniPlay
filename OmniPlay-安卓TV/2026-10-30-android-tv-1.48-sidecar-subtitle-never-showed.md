# 1.48 高性能直出下转档字幕不显示（不报错）

## 现象

1.47 修好「读取字幕文件返回 HTTP 401」之后，用户实测：字幕弹窗里能看到 NAS 转档服务写的
`片名.zh.sup` 与 `片名.zh.srt`，点下去不再报错，但屏幕上一行字幕都没有。给的样本是
`Fallout.S01E01.2024.2160p.AMZN.WEB-DL.DDP5.1.HDR.H.265-HHWEB.zh.srt`（503 条，32415 字节），
配套视频同目录。

## 排查

1. 先用 JVM 探针把这份真实 SRT 过一遍 `parseSubtitleCues`（`/tmp/subparse/SubParseProbe.java`，
   逐字照抄 Activity 里的解析实现）：字符数 23317，解析出 503 条，第一条 `21.0~24.125 剧终`。
   解析不是问题。
2. 在 Activity 里把整条字幕链打上日志（tag `OmniPlay-Sub`）：选用哪条 sidecar、读到多少字节、
   解析出多少条、结果有没有被判过期、覆盖层多久画一次、时间轴命没命中，以及**为什么没自动挂**。
3. Mac Android Subsystem 真机跑（adb `127.0.0.1:58526`）。播放页是 `FLAG_SECURE` 窗口：
   `uiautomator dump` 返回 0 个节点、`screencap` 只有黑屏，所以只能靠日志定位。
   顺带确认虚拟屏要用 `adb shell wm size 1920x1080` 掰成横屏，否则 TV 界面被压成竖屏。

日志直接给出答案（1.47 行为）：

```
播放模式：兼容字幕播放 · Fallout…mkv
现成外挂字幕登记完成，新增 0 条，试着自动挂一条
没有自动挂现成字幕：不是高性能直出（兼容模式下内封字幕由播放器画，不该抢）
```

切到高性能直出之后（遥控器路线：`DPAD_DOWN` 显工具条，`DPAD_RIGHT`×4 走到「模式」，
`DPAD_CENTER` 开菜单，`DOWN`+`CENTER` 选「高性能直出」；第一条 `RIGHT` 只显工具条不移焦，
所以是 4 下不是 3 下）：

```
播放模式：高性能直出 · Fallout…mkv
可以自动挂现成字幕：可用的 2 条，偏好语言 zh
选用 sidecar：媒体源外挂字幕 · 中文（SRT） · Fallout….zh.srt
读到 32415 字节，解析出 503 条（srt）
字幕已挂上：文本 503 条 / 位图 0 条
position=21.1 … 命中 是   （21.1s–24.2s，正是第一条「剧终」）
```

## 根因

两处判断都把「转档字幕」当成不存在，叠加成静默失败：

1. `hasSubtitleSelection()` 只认内封 / 外挂 / 运行时三条路，不含 `selectedSidecarKey`。
   默认字幕那套重试（`scheduleDefaultSubtitleRetries`，700ms / 1.8s / 4.2s / 8.5s）用它做闸门，
   于是每次重试都认为「用户还没选」，把刚挂上的转档字幕换成一条内封轨；直出走
   `vo=mediacodec_embed`，mpv 不参与画面，那条内封轨不上屏，屏幕上就什么都没有。
2. `maybeAutoUseSidecar()` 的闸门含 `selectedEmbeddedSubtitleOrdinal >= 0`，而 `loadDefaultSubtitle()`
   在起播时就"选中"了一条内封字幕——在直出下它本来就画不出来，却把自动挂字幕挡住了。
   另外 `prefindSidecars()` 要求 `discoverSidecars()` 返回值 `> 0`，那个数只统计**新登记**几条，
   重播同一条时是 0，等于重播就永远不自动挂。

## 改动

- 新增 `app/src/main/java/com/omniplay/tv/local/SubtitleSelection.java`：三处判定收成一处纯逻辑——
  `sidecarSelected`（转档字幕算不算选上）、`overlayOwnsSubtitles`（这条片子的字幕归不归 Android
  覆盖层画：`hls || (direct && !iso)`）、`defaultRetryMayTakeOver`（默认字幕重试能不能接手）。
  放在 `local/` 是因为 JVM 自检能直接跑，Activity 只负责把状态递进来。
- `MainActivity.hasSubtitleSelection()` = `SubtitleSelection.sidecarSelected(...) || hasPlainSubtitleSelection()`；
  新增 `hasPlainSubtitleSelection()` 保留原来那六条条件给重试判定用。
- `hasRenderableSubtitleSelection()` 改成调 `defaultRetryMayTakeOver`，`usesAndroidSubtitleOverlay()`
  那侧也换成 `overlayOwnsSubtitles`，两边共用一套口径。
- `clearSubtitleSelection()` 一并清 `selectedSidecarKey` / `activeSidecar`（以前只清内封与外挂，
  菜单里的勾会留在早已换掉的转档字幕上）。
- `loadDefaultSubtitle()` 见已经挑好且读到手上的转档字幕就让路，不再拿内封轨盖上去。
- `maybeAutoUseSidecar()`：闸门改为「覆盖层有没有画着字幕」，直出下「选着一条画不出来的内封轨」
  不再挡路；`prefindSidecars()` 不再要求新增条数 `> 0`；尊重设置里的「关闭字幕」；同语言里优先
  文本字幕（位图要逐条解码，直出下更贵），新增 `firstSidecar(usable, language, wantBitmap)`。
- 字幕菜单顶部新增「关闭字幕」一行（`turnOffAllSubtitles()`）：内封 + 外挂 + 转档一起关，
  以前只能换不能关。
- 日志：`播放模式：…`、`打开播放页菜单：…`、`可以自动挂现成字幕：…`、
  `没有自动挂现成字幕：<原因>`、`读到 N 字节，解析出 N 条（格式）`、`字幕已挂上：…`、
  `position=… 命中 是/否`（去重后打印）。`adb logcat -s OmniPlay-Sub` 一条命令看全链。

## 手机端同步

`PhoneMainActivity.autoLoadFirstSidecar()` 原来自己写了一套挑法（只认 `zh`，否则取第一条），
既不看设置里的「关闭字幕」，也不区分文本与位图。现在电视与手机调同一个
`SubtitleSelection.prefer(usable, language, wantBitmap)`，并同样尊重「关闭字幕」偏好。为此
`LocalEngine.Sidecar(LocalMediaLibrary.SidecarRow)` 的构造放宽成 `public`，自检才能直接造对象。

## 自检

`build/harness/SidecarCheck.java` 补 19 项判定，把上面这些语义钉死：转档字幕在手 / 还在读 /
读超时三种情况下重试各该不该接手；覆盖层模式有没有字幕在手；兼容模式下已经落定的内封字幕
不再被反复重选、还在加载中则留一次补救机会；`overlayOwnsSubtitles` 对直出、直出 ISO、兼容、
HLS 四种组合的归属；`prefer()` 在同语言里先给文本字幕、点名才给位图、没有该语言不硬凑，
以及 `subtitlePreferenceOff` 认 `no` 与 `off`。跑法不变：

```sh
python3 build/patches/mkmkv.py && zsh build/tvtools/harness.sh
# OK 字幕转档 70 项全部通过
```

删掉一条与新语义自相矛盾的旧判定（「内封字幕还在加载，重试别抢」——调用方本来就有一道
「没超时就别动」的闸）。

装上 1.48 最终包重播同一条（不再碰遥控器，偏好已存成高性能直出）：

```
播放模式：高性能直出 · Fallout…mkv
现成外挂字幕登记完成，新增 0 条，试着自动挂一条
可以自动挂现成字幕：可用的 2 条，偏好语言 zh
选用 sidecar：媒体源外挂字幕 · 中文（SRT） · Fallout….zh.srt
读到 32415 字节，解析出 503 条（srt）
字幕已挂上：文本 503 条 / 位图 0 条
…（整场播放 92 个采样点 命中 是，播到 89.4s 自然结束，全程没有「字幕层被清空」）
```

## 遗留

- `OfflineCacheManager.openInput()` / `expectedSize()` 仍然拿未解码的 userinfo 直接拼 Basic 头，
  1.47 只在 `Http` 那条路上做了 URL 解码。这两处目前没有调用方（1.15 起 TV 撤了离线缓存入口），
  属于休眠代码，等真要恢复缓存功能时一并修。
- mp4 的 `mov_text` 内封字幕没有容器级兜底：`MatroskaSubtitleExtractor` 只读 MKV，mp4 只能靠
  mpv 的 `track-list`。兼容模式下够用，直出模式下这类片子仍需要 NAS 那台转档服务先出一版文本字幕。
- MAS 播放页 `FLAG_SECURE`：控件树与截图都拿不到，像素级验证只能上真机；本次以日志的
  `命中 是` 作为覆盖层已画字的证据。
