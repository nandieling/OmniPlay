# 2026-10-08 Windows 版分类文件夹与文件夹详情对齐 ARM Mac 版

把 ARM Mac 版首页「按导演/主演分类」的卡片与文件夹详情页显示方式移植过来。
数据链路（分类、人物档案、作品列表缓存、中文译名）沿用上次的实现，只改展示层。

## 卡片（首页分类文件夹）

- 卡片名称一律居中：影视卡片标题居中、副标题与观影状态按钮整组居中；
  分类文件夹卡片按 mac 版的 `HStack + frame(alignment: .center)` 照搬：
  名称与数量同行、各占一行不换行（名称过长用省略号），整组在卡片宽度内水平居中、
  固定 20px 行高。之前数量跟着 `MinHeight` 沉到第二行，看着像换了行。

- 名称与数量同行居中显示（数量为弱色小字），不再占一整行副标题。
- 文件夹卡片不再有观影状态圆点（那是影片的属性，文件夹上一直是空的）。
- 封面优先级：用户指定封面 > 分类内随机影视海报。随机结果在本轮会话里固定，
  避免每次刷新封面都在跳。
- 文件夹一律按名称排序（升降序仍由首页箭头切换），「未标注」固定排在最后；
  以前文件夹跟着影片的年序/评分序走，换个排序方式文件夹顺序就变。
- 排序按钮的提示语在分类模式下改成「分类文件夹按名称升/降序」。
- 右上角按钮从「自定义文件夹海报」（只有本地选图）改成「自定义编辑」，点开封面编辑器。

## 文件夹详情页

- 进入详情页就是整页视图：继续播放区块和它的分隔线让位（`ShowContinueWatching`）。
- 头部封面 150x225，返回按钮放在封面图上方而不是左边；
  封面右上角有同一个编辑入口，进详情页后也能改封面。
- 详情页隐藏搜索、排序、升降序、分类四个按钮——年表面向前是固定的，
  这些按钮在详情页里只会干扰。
- 封面优先级：用户指定封面 > 导演/主演照片 > 分类内影视海报（兜底）。
  照片必须先落到本地海报目录，Windows 端的图片只认本地路径。
- 头部封面尺寸跟随海报墙卡片尺寸（`LibraryPosterCardWidth/Height`），
  与下方影视海报同大小，不再固定 150x225。
- 说明文字从两行文本换成 mac 版的完整年表：
  标题行「X共执导/参演过 N 部影视」，下面按上映时间正序分六列列出全部作品（mac 是三列，
  win 的详情页是首页内展开、可用高度更小，六列才不会把头部顶得太高），
  同年只在第一部前显示「YYYY：」，没有日期的归到一次「其他：」。
- 计数与条目包含库里还没有、只在人物作品记录里出现的作品：这类条目用弱色，
  库里的作品加粗用强调色，一眼能分辨哪些能直接播。
- 头部下方补一条分隔线，和 mac 版一样把头部与海报墙分开。

## 观影状态图标（首页卡片 + 分集剧照共用）

- 一套三态图标：已看 = 强调色实心圆 + 细对勾；未看完 = 圆环左半实心；
  未看 = 空心圆环（与 mac 的 `circle` 一致，之前加了个播放三角反而像"播放"按钮）。
- 分集剧照不再用黑色半透明蒙层区分已看未看（`EpisodeThumbnailDimOpacity` 已删），
  状态图标放在分集名称右边；未看完继续保留底部进度条，与 mac 版一致。

## 封面编辑器

- 弹窗顶部可改导演/主演名称（对齐 mac 的「编辑「X」」弹窗，「未标注」分组不显示）：
  `ICategoryFolderStore.RenamePersonAsync` 会改写影片名单、文件夹与人物档案主键，
  并记住这个名字，后续刮削不再退回外文名；改名后详情页跟着切到新文件夹。
- 候选海报 = 该分类下所有影视已刮削到的海报（去重、按片名排序、当前封面置顶并标注）。
- 「选择本地图片」走原来的文件选择器；「恢复默认封面」清空档案与旧设置里的记录，
  卡片与详情页退回分类内随机海报。
- 手动封面同时写 `categoryFolder.posterPath` 和旧设置 `HomeFolderPosters`，
  与之前的迁移逻辑保持互通。

## 人物资料只抓一次

- 刮削登记时把 TMDB 的头像相对路径存进 `personProfile.photoPath`
  （以前写死 null，所以 win 端永远拿不到人物照片）。
- 打开详情页时懒下载头像到本地海报目录并改写成本地路径；早期没记路径的档案，
  用 `FetchPersonDetailAsync` 补查一次。
- 作品列表沿用 7 天新鲜的档案缓存；拉取失败或为空记 10 分钟退避，
  本地已有数据时不再显示「（正在获取完整作品列表…）」。

## 顺带

- `unknown` 分组的展示名统一成「未标注」（原来卡片写「未标注」、详情页标题写「其他」）。
- 电影与人物作品记录按 `Movie.TmdbId` 对齐，同一作品以 TMDB 的中文片名与日期为准；
  mac 版拿本地行 id 与 TMDB id 比对，其实对不上。剧集库里没存 TMDB id，退回片名比对。

## 与 mac 版仍有差异

- 详情页是首页内的「展开文件夹」模式（顶部返回箭头），mac 是导航页；工具栏位置随之不同。

## 验证

- `dotnet build src/OmniPlay.UI -c Release`：0 error，警告数与改动前相同（161 条历史 nullable 噪声）。
- `dotnet test`：315 passed / 1 failed，唯一失败项仍是既有的 `TmpDbDumpTests.DumpLiveData`（读固定库文件）。
- 新增 5 项测试：文件夹按名称排序且「未标注」垫底、详情页年表合并本地库与人物作品记录、
  「未标注」文件夹的提示文案、详情页接管整页（继续播放让位）、封面编辑器的候选与落库。
- 界面语言是进程级全局量，`SettingsViewModel.LoadAsync` 会按设置改写它；
  把三个会动到语言的测试类（`PeopleChineseNameTests` / `SettingsViewModelTests` /
  `PosterWallViewModelTests`）放进同一个 xUnit collection，避免并行时互相覆盖。
- 封面编辑器里改名（`RenamePersonAsync`）的测试保留，改名入口仍在这个弹窗里。
- `package-setup.sh` 的载荷校验改成先取 zip 目录再匹配：`unzip | grep -q` 在 `pipefail` 下
  会因为 grep 提前退出、unzip 收到 SIGPIPE 而误报「载荷中缺少 OmniPlay.Desktop.exe」。
- `./package-setup.sh`：安装包与便携包重新生成，PE 架构校验通过。
